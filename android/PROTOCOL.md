# piep サーバーと Android の接続仕様

この文書は、piep サーバーの本棚を Android 版から読み書きするための契約。サーバーは常時動かす単独の
`piep-server`。サーバー側の決まり（棚の送り方・世代・管理の口）は [バックエンドの方針](../docs/policy/06-backend.md)
にある。

## 接続と認証

1. デスクトップ版の「設定 → サーバー（β）」で「携帯を追加」を押すと、一回限りの登録文字列が出る。有効期限は 10 分。
2. 登録文字列は次の形（版 2）。Android は版 2 だけを読み、管理者用（`role` が `admin`）は受け付けない。

   ```json
   {"version":2,"role":"reader","url":"https://…/","secret":"…","fingerprint":null}
   ```

3. `url` は `https://` の任意の host か IP。ポートは省略でき、`https://host/piep/` のようなパス付きでもよい。利用者名・問い合わせ・断片は持てない。
4. `fingerprint` の有無で証明書の検証方法が決まる。
   - **無い:** OS が信頼する CA と host 名で検証する。利用者が足した CA は Android の既定どおり信頼しない。
   - **有る（64 桁の 16 進）:** 自己署名の接続先。無認証の `/hello` で指紋を照合してから登録鍵を送り、以後はその証明書に固定する。証明書が変わっても自動で再登録しない。
5. `POST /pair` で登録鍵を端末用の認証鍵に換える。登録鍵は一度だけ使える。認証鍵は Android のアプリ専用領域に、Keystore の鍵で封じて置く（利用者の認証は求めない）。バックアップと機種間の移行の対象から外し、WebView の JavaScript へ渡さない。
6. 各 API 要求は認証鍵を送る。デスクトップ版で端末ごとに解除でき、解除後は 401 を返す。鍵や登録文字列をログに出さない。

サーバーに配っている棚がまだ無いか、この端末に棚を読む許可が無いときは、接続状態の `issue` を `no_library` にして「デスクトップ版からライブラリを送ってください」と出す。棚を入れ替えるとき、サーバーは立ち上げ直す。そのあいだはつながらない（`offline`）。

## API

共通: `<url>/api`。JSON は UTF-8、属性名は camelCase。要求には大きさの上限がある。誤りは `{code, message}` と HTTP の状態で返し、ローカルのパスや内部の誤りの文字列を返さない。ブラウザー向けの CORS は有効にしない。

### 登録の口

| 操作 | 口 | 応答 |
| --- | --- | --- |
| 接続確認 | `GET /hello`（無認証） | `apiVersion`、`serverName`、`capabilities` |
| 登録 | `POST /pair`（無認証） | 一回限りの登録鍵から端末用の認証鍵を出す |
| 登録の確認 | `GET /about` | 版と名前。解除された端末には 401 |

接続確認では、Rust が登録済みの認証鍵で `GET /api/about` と `GET /api/identity` を確かめる。棚・利用者・同期 epoch のヘッダーがそろえば、接続状態の `shelf` に `scope` を載せる。画面の `pc_*` コマンドはこの `scope` を受け取る。接続先を変えたときや、応答の利用者・棚・同期 epoch が変わったときは、端末の一覧・位置・未送信の書き込みを捨てる。

### 棚を読む口

すべて `Authorization: Bearer …` によるネイティブ通信。Cookie、問い合わせの中の鍵、複数の認証ヘッダー、Origin の付いた要求は受け付けない。鍵や内部のパスを応答に入れない。作品は棚の作品の UUID（文字列）で指す。

| 口 | 用途 |
| --- | --- |
| `GET /identity` | 棚・利用者・同期 epoch・形式・上限。この端末に棚を読む許可が無ければ 401 |
| `GET /libraries/{library}/works?limit&after` | 保存日の新しい順に、棚の作品と今の読書用の版を一ページ（1〜50 件、既定 30）。同じ保存日は作品 UUID の降順 |
| `GET …/works/lookup?provider&key` | 取得元の作品 ID から、棚の作品と今の読書用の版を照合（取得元の名前は 128 バイト、ID はデコード後 4096 バイトまで） |
| `POST …/works/search` | 携帯の一覧：絞り込み・並べ替え・語の検索・ページ送り。本文は `MobileSearchRequest` |
| `GET …/works/suggest?text&limit` | 検索欄の候補（既定 8・上限 12） |
| `GET …/works/{work}` | 作品の画面：今の版のカード・説明・作者とシリーズ・版の一覧（版ごとの写しの ID つき） |
| `GET …/works/{work}/cover?size={card\|large}` | 今の版の表紙を WebP で（320×480 / 640×960 に収める） |
| `PUT …/works/{work}/favorite` | お気に入りを付け外しする（下の「書く口」） |
| `PUT …/works/{work}/reading` | 読書位置を書く（下の「書く口」） |
| `GET …/reading?cursor&limit` | 利用者の読書位置。初めは全部、そのあとは変わった分（既定 200・上限 500） |
| `GET …/works/{work}/collections` | 作品の入ったコレクションと、その中の位置 |
| `GET …/{people\|series}?text&offset&limit&sort&order` | 作者・シリーズの一覧。並べる鍵と向きはデスクトップ版と同じ語彙、続きは `nextOffset` |
| `GET …/{people\|series}/detail?provider&key` | 作者・シリーズの画面の頭：説明・リンク・タグ・シリーズの数・コレクション |
| `GET …/people/series?provider&key&text&sort&order&cursor&limit` | 作者の作品が属するシリーズ |
| `GET …/{people\|series}/cover?provider&key[&variant=banner]` | 作者のアイコン（`banner` はヘッダー）、シリーズの表紙 |
| `GET …/collections` | コレクションの一覧（更新の新しい順） |
| `GET …/collections/{collection}` | コレクションの画面。回の作品は一覧と同じ形 |
| `GET …/collections/{collection}/cover/{single\|file\|tile-0〜3}` | 表紙に選んだ作品の表紙・選んだ画像・先頭からの回の表紙 |
| `GET …/entities/{entity}/views/{snapshot\|edit}/{view}/bundle` | 読書 bundle：読書用の文書と、渡せる全部の資産の file 記述を一回で |
| `GET …/views/{snapshot\|edit}/{view}/resources/{body\|media\|file}/manifest` | 所属と表示の版を固めた一ファイルの記述。media と file は `slot` が要る |
| `GET …/resources/{kind}/files/{file}/chunks/{ordinal}` | 指定した元ファイルの一部分を、保管の形のまま |

- **続きの位置。** 一覧の `next` は手を加えずに次の `after` へ渡す。`null` なら終わり。続きの位置は棚・同期 epoch・利用者に結び付き、違えば 409（`stale_cursor`）なので最初から読み直す。ページ番号で開いたページには続きの位置を付けない。件数は最初のページだけ数える
- **検索。** 語の検索は、配る写しの索引が棚に追いつくまで 503（`search_indexing`）で断る。絞り込みだけの一覧は先に答える。知らない項目・範囲外・重なる指定は 400
- **編集。** 一覧と照合の `editId` は、認証した利用者が反映している編集を指す。編集の bundle・manifest・部分では、その利用者が反映中か以前の編集版に残しているかを確かめる
- **出さないもの。** 取得したそのままの応答は内部の情報を含みうるので出さない。file は利用者向けの添付と文書に限る。未保存の資産は bundle に載せない。棚から外した作品は、作品の画面も表紙も 404
- **所属の確認。** ハッシュだけを指す口は無い。manifest と部分の両方で、要求した作品と版からその実体へ届くかを確かめ直す。表紙は作品のカードから引く
- **ヘッダー。** 認証のあとの応答には `x-piep-library-id`・`x-piep-subject-id`・`x-piep-sync-epoch` が付く（409 にも付くので、棚の入れ替わりと見分けられる）
- **同時数。** 同時に読めるのは端末ごとに 4 件、全部の端末で 8 件。空きがなければ最大 2 秒待ち、それでもなければ 429 と `Retry-After: 1`。一台が全体を占めない
- **キャッシュ。** 部分は中身のハッシュで指すので、持っていれば取らない。ETag と 304 は持たない。部分には `private, max-age=31536000, immutable, no-transform`、記録（一覧・照合・bundle・manifest）には `private, no-cache, no-transform`、どちらにも `Vary: Authorization`。圧縮済みの実体を圧縮し直さない

### 書く口

携帯が棚へ書けるのは、お気に入りと読書位置だけ。どちらも要求 UUID と期待する更新世代を添え、端末の時刻で勝者を決めない。

**お気に入り**の本文は `{"requestId": "<UUID>", "expected": "<十進の更新世代>", "favorite": true|false}`。知らない項目は 400。`expected` は一覧や作品の画面の `favoriteGeneration`（行が無ければ `"0"`）か、前の付け外しで返った `generation`。符号・空白・先頭の 0 の重ねは 400。

- 成功すると `{"favorite": …, "generation": "<十進>"}`。同じ `requestId` を送り直すと、棚に残した受領をそのまま返し、世代は進まない
- 世代が違う（ほかの端末やデスクトップで先に変わった）か、同じ `requestId` を別の変更に使ったときは 409 `{"error": "favorite_conflict", "current": {"favorite": …, "generation": …}}`
- 棚に無い作品・外した作品は 404、棚が書き込み中なら 503 `busy`

**読書位置**は、読む画面のページ（本文の区切りで数えた 0 からの番号）とその中の割合（百万分率）で、読んでいた版の写しか編集に結ぶ：`{"viewKind": "snapshot"|"edit", "viewId": "<UUID>", "page": n, "ratioPpm": n}`。デスクトップの読む画面と同じ形なので、同じ利用者の位置はデスクトップと携帯で共通。

- 本文は `{"requestId", "expected", "location", "finished"}`。受領・世代・409 の扱いはお気に入りと同じで、409 は `{"error": "reading_conflict", "current": <位置>}`。本文に無いページ・別の作品の版・利用者が読めない編集は 400、棚に無い作品は 404
- 返す位置は `{"work", "location", "finished", "mine", "updatedAt", "generation"}`。`location` が空なのは、消した位置かページで表せない位置。`mine` は要求した端末が書いた位置か
- 一覧は `cursor` を空で始めると利用者の位置を全部返し、返し終えると変わった分の印になる。印は棚の変更の記録の番号で、返し始める前に控えるので、途中で変わった位置も次で届く。印には同期の世代が入り、別の写しの印は 400 `reading_cursor_expired`（端末は空から取り直す）

デスクトップ版は、棚の持ち主の位置とお気に入りを `/api/admin/shelf/reading`・`/api/admin/shelf/favorites` から取り込む。

## 読み込みの方針

- **本文は端末で組む。** 作品を開くと、Rust が棚から読書 bundle（読書用文書と、渡せる全資産の file 記述）を受け取り、デスクトップ版と同じ組み立てでページを作る。組んだものは数冊ぶんだけ覚え、消えていたら開き直す。
- **挿絵は `pcimg` で受け取る。** Rust 側が認証と検査（一辺 8192・16Mi 画素・展開 64MiB。保存と同じ上限）を済ませ、JavaScript へ base64 で渡さない。GIF・動く WebP・APNG は最大 256 フレーム、全フレーム合計 32Mi 画素までを実デコードで確認する。アプリのキャッシュ領域に残るが、作品の保存とは別で、OS や容量整理で消える。容量は起動中も一時ファイル込みで 300MiB 以内に収め、超過が見込まれる書き込みの前に古い画像から 240MiB 以下へ整理する。ディレクトリの索引化は初回だけで、その後は増分管理する。索引を読み取れないときはキャッシュへの書き込みを見送り、次回に再試行する。
- **通信。** HTTP/2 で一本の接続に載せ、待ち時間 120 秒まで接続を保つ。応答は gzip を頼む（サーバーは JSON だけ圧縮し、画像はそのまま）。読書位置の同期は開くときに最大 0.6 秒だけ待つ。
- **接続先が変わったら** 一覧・カーソル・詳細・組んだ本文と履歴、お気に入りの表示用の変更を捨てる。前の接続へ送ったお気に入りの遅延応答は採らない。「続きを読む」は接続先ごとに分ける。保存版との照合と削除は `source` と `sourceId` まで確かめる。
- **画像の接続先も固定する。** 画像キャッシュの名前空間を決めた登録で通信し、待ち行列や受信中に登録が変わったら公開・保存しない。照合からキャッシュへの書き込みまで登録変更と排他にする。WebView の画像 URL も起動・接続変更ごとに分け、Rust を通る前に前の接続の HTTP キャッシュから画像が返らないようにする。保存した作品の画像 URL はこの変更に含めない。

## オフライン保存の版の確認

保存は、読む画面と同じ読書 bundle から同じ組み立てでページを作り、作品の画面で見た版（版の写しと編集の UUID）と、受け取り始めと終わりに照合した版が同じときだけ公開する。途中で改稿・編集されていれば、混ざった版へ切り替えない。通信・画像検証・版の照合・公開ポインターの更新に失敗した場合も、現在のスナップショットを保持する。保存中断で残った作業領域は次回起動時に回収する。

保存した作品の置き場は `shelf-{作品の UUID}`。

## 読書位置の同期

設定「読書位置を同期する」（既定は入）が入で、棚に届いているときだけ行う。位置は棚から開いた本（版の写しか編集）に結び、要求 UUID と手元の更新世代を添えて書く。形は上の「書く口」。

- **読む:** 読書画面を開くときと、アプリへ戻ったとき。開くときは短く待ち、間に合えば手元より新しい位置から開く。遅れて届いた位置や読書中に届いた位置では画面を動かさず、「そこへ移動」を案内する。
- **書く:** ページ移動・スクロールの数秒後と、画面を閉じるとき・アプリを離れるとき。まず端末の SQLite に置き、通信はそのあとで行うので読書を止めない。圏外で読んだ分は残り、次につながったときに届く。
- **同期を重ねない:** 同期中の追加送信要求はまとめ、進行中の同期のあとに一回だけ実行する。追加実行の前に同期設定を切った場合は送らない。
- **版が違うとき:** 同じ版の写しか編集で読んでいた位置だけ割合を使う。違えばページを目安にし、ページ数を超えていれば最初から読む。
- **競合:** 端末の時刻で勝者を決めない。別の端末やデスクトップが先に読み進めていれば 409 と今の位置が返る。

## 端末の記録

端末に残す記録は、アプリのデータ領域の `piep.sqlite3` ひとつにまとめる。`PRAGMA user_version` で版を持ち（今は 6）、版ごとの変更は一つの transaction で行う。アプリより新しい版のファイルは開かず、`device_records` を返す。

| 表 | 中身 | 正 |
|---|---|---|
| `shelf_positions`・`shelf_pending`・`shelf_reading_meta` | 棚と同期する読書位置と未送信分 | SQLite |
| `readings` | この端末で読んだ位置・時刻・進み具合と「続きを読む」 | SQLite |
| `offline_catalog`・`offline_text` | 保存した作品の本文の索引（FTS5 trigram） | 保存した本文のファイル |

- **読書位置と「続きを読む」:** `readings` に置き、作品を `source` と `sourceId` で見分ける。位置は版・編集の印が今の本文と同じときだけ使う。作品を開く前に記録を読み終えてから画面を出すので、開く位置や「続きから読む」が後から変わらない。アプリを離れるときと読書画面を閉じるときは、書きかけの記録を送り終える。
- **記録の形:** 表の形は `user_version` で数える。形の違う古い記録は移さずに作り直す（試しの段階のため）。新しい版で作った記録は書き換えない。
- **本文の検索:** 保存した作品の本文を、端末だけで語から探せる。索引は保存・保存し直し・削除のたびに書き換え、検索の前には保存版の世代と見比べて、ずれていれば作り直す。索引が壊れても本文は失われず、作り直せる。日本語は語の切れ目が無いので 3 文字ずつ引き、2 文字以下の語は本文を順に見る。空白で区切った語はすべて含む作品だけを返し、ルビの読みは検索の対象にしない。結果は最初に見つかったページと前後の文で、押すとそのページの頭から開く。
- **SQLite に置かないもの:** 本文と画像はファイルのまま（保存版の切り替えを rename で行うため）。接続の認証鍵は専用のファイル。画面の設定は localStorage。

## お気に入りの書き込み

棚に届いているときだけ、カード・詳細・読書画面のお気に入りを押せる。圏外と端末内の画面では、お気に入りの作品に赤い印を出すだけにする。

- **送る:** 押したらすぐ画面を変え、Rust 側の `pc_set_favorite` が要求 UUID と画面が知っている更新世代を添えて `PUT` する。認証鍵は Rust 側だけが持つ。別の端末やデスクトップで先に変わっていれば、今の値に合わせて一言知らせる。
- **溜めない:** 圏外で押せる形を見せないので、送れなかった変更を端末に残さない。失敗したら元の値に戻して一言知らせる。
- **そろえる:** 返ってきた値を、同じ作品を出している一覧・詳細・読書画面のすべてに当てる。サイドバーの件数と、お気に入りで絞った一覧を読み直す。書き込み完了後に始めた読み取りの値は、新しい正として採用する。書き込み前に始めた遅い応答では戻さない。
- **デスクトップ版へ:** デスクトップ版は棚の持ち主の変更を `/api/admin/shelf/favorites` から取り込む。
- **端末の保存:** 保存した作品の控えは保存したときの値のまま。次に保存し直すと新しい値になる。
- **連続読書中の保存更新:** 最初に読み込んだ本文の保存世代を固定する。次の区切りが別の世代なら、保持していた区切りを捨てて読み直し、旧版と新版の本文を混ぜない。

## 公開データの境界

- 棚の内部の置き場や Windows の絶対パスを応答に含めない。公開専用の形で返す。
- 本文 HTML の `data-local-path` は、その作品に属するアセットを確認した上で不透明な `data-asset-id` に置き換える。対応しない参照は失敗または欠損表示とし、元のパスを残さない。Android 側でも危険な HTML 要素・属性と URL を取り除いてから表示する。
- 画像の `{assetId}` は要求された作品に属するものだけを返す。PC の任意のパスを API 引数にしない。ファイルサイズと画像 MIME 型を制限する。
- 作者アイコン・シリーズ表紙は PC 側で保存先を検証してから画像だけを返す。端末へ元ファイルのパスを渡さない。
- Android 側の表示設定は端末内に持つ。読書位置はサーバーの本棚とは別の表に持ち、本棚の原本を書き換えない。オフライン保存は本文と必要な画像を一つの版として検証後に切り替える。
