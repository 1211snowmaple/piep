# piep サーバーと Android の接続仕様

この文書は piep サーバーの本棚を、別アプリである Android 版から読むための契約。サーバーは、デスクトップ版に内蔵したものと、常時動かす単独の `piep-server` のどちらでもよく、API は同じ。サーバー側の全体像はデスクトップ版の `docs/plan/server-mode.md` にある。

## 接続と認証

1. デスクトップ版の「設定 → サーバー（β）」で「携帯を追加」を押すと、一回限りの登録文字列が出る。有効期限は 10 分。
2. 登録文字列は次の形（版 2）。Android は版 2 だけを読み、管理者用（`role` が `admin`）は受け付けない。

   ```json
   {"version":2,"role":"reader","url":"https://…/","secret":"…","fingerprint":null}
   ```

3. `url` は `https://` の任意の host か IP。ポートは省略でき、`https://host/piep/` のようなパス付きでもよい。利用者名・問い合わせ・断片は持てない。
4. `fingerprint` の有無で証明書の検証方法が決まる。
   - **無い:** OS が信頼する CA と host 名で検証する（Tailscale Funnel、Let's Encrypt など）。利用者が足した CA は Android の既定どおり信頼しない。
   - **有る（64 桁の 16 進）:** 自己署名の接続先。無認証の `/hello` で指紋を照合してから登録鍵を送り、以後はその証明書に固定する。証明書が変わっても自動で再登録しない。
5. `POST /pair` で登録鍵を端末用の認証鍵に換える。登録鍵は一度だけ使える。認証鍵は Android のアプリ専用領域に、Keystore の鍵で封じて置く（利用者の認証は求めない）。バックアップと機種間の移行の対象から外し、WebView の JavaScript へ渡さない。
6. 各 API 要求は認証鍵を送る。デスクトップ版で端末ごとに解除でき、解除後は 401 を返す。鍵や登録文字列をログに出さない。

サーバーに配信中の棚がまだ無いときは、接続状態の `issue` を `no_library` にして「デスクトップ版からライブラリを送ってください」と出す。棚の差し替えの間は 503（`library_not_ready`）を返す。Android はこれを「準備中」と表示する。

## API

共通: `<url>/api/v2`。JSON は UTF-8、属性名は camelCase。リクエストはサイズ上限を設ける。エラーは `{code, message}` と HTTP ステータスで返し、ローカルファイルパスや内部エラー文字列を返さない。ブラウザー向け CORS は有効にしない。旧 API（`/api/v1`）は無くした。

| 操作 | エンドポイント | 応答 |
| --- | --- | --- |
| 接続確認 | `GET /hello`（無認証） | `apiVersion`、`serverName`、`capabilities` |
| 登録 | `POST /pair`（無認証） | 一回限りの登録鍵から端末用認証鍵を発行 |
| 登録の確認 | `GET /about` | 版と名前。解除された端末には 401 |
| 棚の確認 | `GET /identity` | 棚・利用者・同期 epoch。この端末に棚を読む許可が無ければ 401 |
| 一覧・作品・本文・画像・位置・お気に入り | `/libraries/{library}/…` | [新ライブラリの認証付き資産 API](../docs/plan/library-api-v2.md) |

接続確認の際、Rust が登録済みの認証鍵で `GET /api/v2/about` と `GET /api/v2/identity` を確かめる。棚・利用者・同期 epoch のヘッダーが一致すれば、接続状態の `nativeLibrary` に `scope` を載せる。画面の `pc_native_*` コマンドはこの `scope` を受け取る。接続先を変更した場合や、応答の利用者・棚・同期 epoch が変わった場合は一覧を開き直す。携帯ごとの棚を読む許可は、デスクトップ版の画面で付け外しする。

作品は棚の作品の UUID（文字列）で指す。一覧・作品の画面・作者とシリーズ・コレクション・検索欄の候補・以前の版は、すべて棚から引く。棚に届かない接続では一覧を出さず、端末に保存した作品だけを読める。

## 読み込みの方針

- **本文は端末で組む。** 作品を開くと、Rust が棚から読書 bundle（読書用文書と、渡せる全資産の file 記述）を受け取り、デスクトップ版と同じ組み立てでページを作る。組んだものは数冊ぶんだけ覚え、消えていたら開き直す。
- **挿絵は `pcimg` で受け取る。** Rust 側が認証と検査（一辺 8192・16Mi 画素・展開 64MiB。保存と同じ上限）を済ませ、JavaScript へ base64 で渡さない。GIF・動く WebP・APNG は最大 256 フレーム、全フレーム合計 32Mi 画素までを実デコードで確認する。アプリのキャッシュ領域に残るが、作品の保存とは別で、OS や容量整理で消える。容量は起動中も一時ファイル込みで 300MiB 以内に収め、超過が見込まれる書き込みの前に古い画像から 240MiB 以下へ整理する。ディレクトリの索引化は初回だけで、その後は増分管理する。索引を読み取れないときはキャッシュへの書き込みを見送り、次回に再試行する。
- **通信。** HTTP/2 で一本の接続に載せ、待ち時間 120 秒まで接続を保つ。応答は gzip を頼む（サーバーは JSON だけ圧縮し、画像はそのまま）。読書位置の同期は開くときに最大 0.6 秒だけ待つ。
- **接続先が変わったら** 一覧・カーソル・詳細・組んだ本文と履歴、お気に入りの表示用の変更を捨てる。前の接続へ送ったお気に入りの遅延応答は採らない。「続きを読む」は接続先ごとに分ける。保存版との照合と削除は `source` と `sourceId` まで確かめる。
- **画像の接続先も固定する。** 画像キャッシュの名前空間を決めた登録で通信し、待ち行列や受信中に登録が変わったら公開・保存しない。照合からキャッシュへの書き込みまで登録変更と排他にする。WebView の画像 URL も起動・接続変更ごとに分け、Rust を通る前に前の接続の HTTP キャッシュから画像が返らないようにする。保存した作品の画像 URL はこの変更に含めない。

## オフライン保存の版の確認

保存は、読む画面と同じ読書 bundle から同じ組み立てでページを作り、作品の画面で見た版（版の写しと編集の UUID）と、受け取り始めと終わりに照合した版が同じときだけ公開する。途中で改稿・編集されていれば、混ざった版へ切り替えない。通信・画像検証・版の照合・公開ポインターの更新に失敗した場合も、現在のスナップショットを保持する。保存中断で残った作業領域は次回起動時に回収する。

保存した作品の置き場は `shelf-{作品の UUID}`。旧 API で保存した `work-{番号}` の置き場は読まない（携帯は試用だけだったので移さない）。

## 読書位置の同期

設定「読書位置を同期する」（既定は入）が入で、棚に届いているときだけ行う。位置は棚から開いた本（版の写しか編集）に結び、要求 UUID と手元の更新世代を添えて書く。詳しい形は [読書位置](../docs/plan/library-api-v2.md#読書位置)。

- **読む:** 読書画面を開くときと、アプリへ戻ったとき。開くときは短く待ち、間に合えば手元より新しい位置から開く。遅れて届いた位置や読書中に届いた位置では画面を動かさず、「そこへ移動」を案内する。
- **書く:** ページ移動・スクロールの数秒後と、画面を閉じるとき・アプリを離れるとき。まず端末の SQLite に置き、通信はそのあとで行うので読書を止めない。圏外で読んだ分は残り、次につながったときに届く。
- **同期を重ねない:** 同期中の追加送信要求はまとめ、進行中の同期のあとに一回だけ実行する。追加実行の前に同期設定を切った場合は送らない。
- **版が違うとき:** 同じ版の写しか編集で読んでいた位置だけ割合を使う。違えばページを目安にし、ページ数を超えていれば最初から読む。
- **競合:** 端末の時刻で勝者を決めない。別の端末やデスクトップが先に読み進めていれば 409 と今の位置が返る。

## 端末の記録（0.6.0 から）

端末に残す記録は、アプリのデータ領域の `piep.sqlite3` ひとつにまとめる。`PRAGMA user_version` で版を持ち（今は 6）、版ごとの変更は一つの transaction で行う。アプリより新しい版のファイルは開かず、`device_records` を返す。

| 表 | 中身 | 正 |
|---|---|---|
| `shelf_positions`・`shelf_pending`・`shelf_reading_meta` | 棚と同期する読書位置と未送信分 | SQLite |
| `readings` | この端末で読んだ位置・時刻・進み具合と「続きを読む」 | SQLite |
| `offline_catalog`・`offline_text` | 保存した作品の本文の索引（FTS5 trigram） | 保存した本文のファイル |

- **読書位置と「続きを読む」:** `readings` に置き、作品を `source` と `sourceId` で見分ける。位置は版・編集の印が今の本文と同じときだけ使う。作品を開く前に記録を読み終えてから画面を出すので、開く位置や「続きから読む」が後から変わらない。アプリを離れるときと読書画面を閉じるときは、書きかけの記録を送り終える。
- **旧 API の記録:** 版 6 で旧 API の同期の表（`positions`・`pending`・`sync_meta`）を捨てた。0.5 までの localStorage と `reading-sync.*` からの移行も無くした。
- **本文の検索:** 保存した作品の本文を、端末だけで語から探せる。索引は保存・保存し直し・削除のたびに書き換え、検索の前には保存版の世代と見比べて、ずれていれば作り直す。索引が壊れても本文は失われず、作り直せる。日本語は語の切れ目が無いので 3 文字ずつ引き、2 文字以下の語は本文を順に見る。空白で区切った語はすべて含む作品だけを返し、ルビの読みは検索の対象にしない。結果は最初に見つかったページと前後の文で、押すとそのページの頭から開く。
- **SQLite に置かないもの:** 本文と画像はファイルのまま（保存版の切り替えを rename で行うため）。接続の認証鍵は専用のファイル。画面の設定は localStorage。

## お気に入りの書き込み

棚に届いているときだけ、カード・詳細・読書画面のお気に入りを押せる。圏外と端末内の画面では、お気に入りの作品に赤い印を出すだけにする。

- **送る:** 押したらすぐ画面を変え、Rust 側の `pc_native_set_favorite` が要求 UUID と画面が知っている更新世代を添えて `PUT` する。認証鍵は Rust 側だけが持つ。別の端末やデスクトップで先に変わっていれば、今の値に合わせて一言知らせる。
- **溜めない:** 圏外で押せる形を見せないので、送れなかった変更を端末に残さない。失敗したら元の値に戻して一言知らせる。
- **そろえる:** 返ってきた値を、同じ作品を出している一覧・詳細・読書画面のすべてに当てる。サイドバーの件数と、お気に入りで絞った一覧を読み直す。書き込み完了後に始めた読み取りの値は、新しい正として採用する。書き込み前に始めた遅い応答では戻さない。
- **デスクトップ版へ:** デスクトップ版は棚の持ち主の変更を `/api/v2/admin/shelf/favorites` から取り込む。
- **端末の保存:** 保存した作品の控えは保存したときの値のまま。次に保存し直すと新しい値になる。
- **連続読書中の保存更新:** 最初に読み込んだ本文の保存世代を固定する。次の区切りが別の世代なら、保持していた区切りを捨てて読み直し、旧版と新版の本文を混ぜない。

## 公開データの境界

- 棚の内部の置き場や Windows の絶対パスを応答に含めない。公開専用の形で返す。
- 本文 HTML の `data-local-path` は、その作品に属するアセットを確認した上で不透明な `data-asset-id` に置き換える。対応しない参照は失敗または欠損表示とし、元のパスを残さない。Android 側でも危険な HTML 要素・属性と URL を取り除いてから表示する。
- 画像の `{assetId}` は要求された作品に属するものだけを返す。PC の任意のパスを API 引数にしない。ファイルサイズと画像 MIME 型を制限する。
- 作者アイコン・シリーズ表紙は PC 側で保存先を検証してから画像だけを返す。端末へ元ファイルのパスを渡さない。
- Android 側の表示設定は端末内に持つ。読書位置はサーバーの本棚とは別の表に持ち、本棚の原本を書き換えない。オフライン保存は本文と必要な画像を一つの版として検証後に切り替える。

## 2026-10-12 の実ライブラリ確認

- スマホ・タブレットのエミュレーターで、作者・シリーズ・コレクションの各一覧から所属作品を開いた。検索要求の絞り込みには `kind`・`source`・`key` だけを送る。

- 選択保存した作品の作者・シリーズ・コレクションを端末内で分類し、PC 接続を切った状態でも保存済み本文を取得した。以前に保存した作品のコレクション所属は、PC に接続して保存し直すと反映する。
- 選択保存時に作者アイコンとシリーズ表紙も端末へ保存し、PC 接続を切った状態で画像を取得した。旧スナップショットは読み込み可能で、これらの画像は保存し直すと追加される。

## 最初の検証

- 共有停止中はポートが開かず、停止後に新しい要求を受け付けない。
- 未登録・誤った鍵・解除済み端末から本文と画像を取得できない。
- 検索・作品情報・本文の JSON に `jsonPath`、`coverPath`、`localPath` や PC のアプリデータディレクトリが出ない。
- カーソルを使って全作品を辿れ、編集済み本文・章・挿絵を PC 版と同じ内容で読める。
- 証明書指紋の不一致と接続不能を Android 側で区別する。PC 終了と Wi-Fi 切断はいずれも接続不能として扱う。

## 2026-10-10 の結合確認

- PC 側の一時 DB の 2 ページ作品を、Android のスマホ・タブレット両エミュレーターから HTTPS で登録・検索・閲覧した。登録済み端末の認証鍵は Android のアプリ専用領域に保存された。
- 本文の画像参照は PC 側で `data-asset-id` に変換され、Android は認証付きで画像を取得して表示した。Windows の絶対パスは検索・本文 API の応答に出さない。
- 作品を端末内へ保存し、PC サーバーを停止してから本文・画像を表示した。アプリ強制終了後も保存作品と読書位置を復元した。
- 画面を APK に同梱してタブレットエミュレーターへ配置し、PC 共有と Vite 開発サーバーを止めた状態でも保存本文と画像を読めた。
- 機内モード中にアプリを再起動しても保存本文を開けた。確認後、通信設定を元に戻した。
- 端末で再保存したときは新しいスナップショットへの切り替え後に旧版を削除する。ページと画像には SHA-256 検証値を記録する。
- 検証用サーバーは `src-tauri/examples/mobile_bridge_probe.rs`。実作品の全ケースと物理 Wi-Fi・実機は今後確認する。

## 2026-10-11 の表示・更新確認

- 一時 DB の長文で転送ページが原稿ページより多くなる状態を作り、ルビ・見出し・改ページ・原稿ページへの移動・挿絵・外部リンクを Android の画面で確認した。リンク先は http/https に限定して外部ブラウザーで開く。
- アセットファイルを一時的に欠かすとオンライン読書に欠損を表示する。保存を再実行しても既存のスナップショットは切り替わらず、保存済み本文と画像を読めた。アセットファイルは検証後に復元した。
- 反映済み編集作品の本文は検索とページ API に反映される。保存済み作品だけ追加で作品情報の編集ハッシュを取得し、元作品の版が同じでも編集内容が変われば「更新あり」と表示する。再保存後は新しい編集内容をオフラインで読める。
- 長文の保存版は、PC 共有停止後かつ機内モードでアプリを再起動しても読めた。Android の戻るキーで本棚へ戻り、スマホとタブレットの縦横表示を確認した。

## 2026-11-02 の版 2 の結合確認

本棚の一部（120 作品）を入れた単独サーバーへ、スマホとタブレットのエミュレーターから自己署名の TLS でつないで確かめた。

- 画面から 2 台を登録し、本文を読んだ。v1 の文字列・管理者用・http の URL・違う指紋は通信の前か登録鍵を送る前に断り、鍵の誤りも登録にならない。
- 指紋の無い登録文字列は端末の CA で検証する。公開サイトで、正しい証明書は TLS を通り（piep でないので形式違いと表示）、host 名違い・期限切れ・自己署名は「証明書を確認できません」と断った。
- スマホで読んだ位置からタブレットが開く。開いただけでは書かない。読書中に届いた位置では動かず、案内から移動できる。移動しても書き戻さない。
- サーバーを止めている間に読んだ位置は、再開後にアプリへ戻ると届く。止まっている間は、通信状態とサーバーの状態を確かめるよう案内する。接続の種類で文言を変えない。
- 版が違う位置はページだけを目安にし、ページ数を超えていれば最初から開く。設定を切ると送らない。端末への保存と、保存した本文の読み出しはそのまま動く。

Tailscale Funnel の実経路と実機は未確認。

## 読書・検索の読取 API 追加（2026-11-07）

既存の版2登録と `/api/v1` を維持し、認証済み読み手向けに次を追加した。

- `search-suggest`: `GET /api/v1/search/suggest?text=...&limit=8`。デスクトップの候補生成を使い、検索語は200文字・応答は最大12候補。Android はこの機能が通知されたときだけ検索欄に候補を出す。
- `work-lookup`: `GET /api/v1/works/lookup?source=...&key=...`。取得元と作品IDから、公開用作品情報または `null` を返す。本文リンクからライブラリ内の読書画面を開くために使う。内部パスは返さない。
- ページ・目次の `?version=N` を Android から選べるようにした。ページの `revision` は明示した原文の版・ハッシュを示し、現在の編集版のハッシュは付けない。
- 作者の `cover` はプロフィールアイコンだけを返す。背景は `variant=banner`。`hasCover` と `hasBanner` も独立に判定する。

検索候補と本文リンクの作品照合、作者画像の修正には対応するサーバーへの更新が必要。旧サーバーでの通常検索と既存の読書は継続できる。
