# ライブラリの転送契約

`piep-resource-transfer-v1` は、棚・対象・保存状態・資産へ固定した **一つの元ファイル** の
転送記録。読書 bundle や API v2 の完成・認証を表す形式ではない。

- UUID は空でない標準形、SHA-256 は小文字の 64 文字、u64 は十進文字列。
  JavaScript の整数精度を経由せず、元ファイルの内側の serde 表現とも分離する。
- ファイルは最大 512 MiB、本文ファイルと記録 JSON はそれぞれ最大 16 MiB。chunk は読み取り中から 128 個までに
  制限し、分割位置・個数・長さは `piep-storage` と同じ v1 の検査を使う。
- 未対応の版・未知の項目・重複項目を拒否する。認証鍵・接続世代・絶対パスを含めない。
  slot は DB で照合する不透明な識別子で、ファイルパスとして解釈しない。
- 受信記録の ID は整形前の JSON バイト列の SHA-256。検査済みの記録は元バイト列を保持する。
  API の認証や必要な権限は別途照合し、記録のハッシュを知っているだけで読めるようにしない。
- 展開したファイル全体の SHA-256 は受信後にも検査する。構造が正しい記録を読めても、
  chunk が未受信なら保存完了ではない。保存状態の切り替えは端末 DB の責務になる。

デスクトップは `Library::resource_transfer_manifest` と `export_resource_chunk` を使う。
後者は毎回、作品等への所属・資産・file ID・部分の順番を照合してから圧縮済み実体を渡す。
HTTP の認証と利用者 ACL はその外側で必要。現行サーバーにはまだ有効化しない。

内部の保管形式や DB スキーマを wire DTO に直接しない。今後の bundle や epoch 付き同期の
DTO もこの crate に追加するが、独立した版と受け入れ条件を持たせる。
