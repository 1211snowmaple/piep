# 表紙のない作品のカード表示 — 意匠の提案レポート

実施日: 2026-08-16
更新: 2026-08-17 — **C-1（背表紙）と C-6（identicon）を合成して実装した。**
対象: `src/components/WorkCover.tsx`、`src/lib/coverSigil.ts`、`src/styles/app.css`（`.work-cover*`）、および EPUB 側への転用

## 実装したもの（2026-08-17）

```
┌──────────────┐
│▔▔▔▔▔▔▔▔▔▔▔▔▔▔│ 提供元の細帯（現状どおり）
│ ■ ■          │ 印 = 作品IDから決まる 5×5 の左右対称パターン（C-6）
│  ■■■         │
│              │
│  シリーズ名   │ ← あるときだけ
│  タイトル     │ ← 主役。文字数で3段階（C-1）
└──────────────┘   地色 = 作者名から決まる12段の色相
```

- **印は作品ごと、色は作者ごと。** 同じ棚に同じ絵が並ばず、同じ作者の作品は同じ色でまとまる。
- **46px（リスト表示）では印だけ**にする。文字が読めない大きさに文字を置かない。
- **作者名はタイルに書かない。** カード本体がすぐ隣に出しているため、色で示すに留めた。
- 色相は12段に量子化した。`hash % 360` は日本語の作者名が近い値に固まり、9人中4人が同じ緑になったため、
  FNV-1a で混ぜてから12段に落としている（`src/lib/coverSigil.ts`）。

検証: `src/lib/coverSigil.test.ts`（決定論性・作者ごとの一致・左右対称・色相の分布）と、
実データに近いデモ12件でのスクリーンショット（`docs/screenshots/library-light.png` / `-dark.png`）。

## 1. 現状

### 1-1. 何が描かれているか

`WorkCover` は `coverPath` が無い（または画像の読み込みに失敗した）とき、`.work-cover__empty` を描く。

```tsx
<Box className="work-cover__empty" role="img" aria-label={`${work.title}（表紙なし）`}>
  <Icons.read className="work-cover__empty-icon" strokeWidth={1.35} aria-hidden />
  <Text className="work-cover__empty-kicker">{contentTypeLabel(work.contentType)}</Text>
  {variant === "detail" && <Text className="work-cover__empty-title line-clamp-3">{work.title}</Text>}
</Box>
```

意匠は CSS の 3 枚重ねでできている。

| 層 | 内容 |
|---|---|
| 上端 | `--work-cover-accent`（提供元の色）の 3px 帯、`opacity: .72` |
| 縦罫 | 左から 18px の位置に 1本（原稿用紙の版面罫のつもり） |
| 横罫 | 23px ごとの繰り返し（`rgb(35 43 52 / 4%)`） |
| 図像 | 「読む」アイコン（幅 30%、最大 54px）＋ 種別ラベル |

variant は 3 つ。`compact`（46×58、行表示では 52×70）はラベルを隠す。`card` は `aspect-ratio: 112/158`。`detail` だけタイトルを 3 行まで出す。

### 1-2. 何が困るか

**同じ絵が並ぶ。** アクセント色は提供元ごとに 1 色（pixiv `#0096FA` / FANBOX `#F2C624`）しかないので、表紙のない FANBOX の投稿を 40 件並べると、**40 枚が完全に同一のタイル**になる。FANBOX は表紙を持たない投稿が多く、実際のライブラリでは「表紙なし」が例外ではない。

| 問題 | 内容 |
|---|---|
| P1 | 作品どうしを見分けられない（位置でしか区別できない） |
| P2 | タイルが情報を持たない（`card` ではタイトルすら出ない。右の本文側にはあるが、目は先に絵を見る） |
| P3 | 「読む」アイコンが**操作**（カード内の「読む」ボタン）と同じ字形で、押せそうに見える |
| P4 | 種別ラベル（小説／記事）は 9px の全大文字指定だが、中身は日本語なので `text-transform: uppercase` が効かない |
| P5 | EPUB 側は「表紙が無ければ表紙ページごと省略」なので、書き出した本にも扉が無い |

---

## 2. どの案も満たすべき条件

1. **46px 角でも成立する。** 行表示のサムネイルが最小サイズ。文字を詰めても読めないので、小さいときは要素を減らす方針を各案が持つこと。
2. **実データで破綻しない。** 100 文字のタイトル、絵文字だけのタイトル、英数字のみ、空文字。
3. **決定論的である。** 同じ作品はいつ見ても同じ絵。乱数や取得順に依存しない（再描画・再起動・別マシンで変わらない）。
4. **色は増やしすぎない。** [配色レポート](color-system-proposal-2026-08-11.md) の結論どおり、一覧は静かであるべき。彩度は抑え、面ではなく差で見分けさせる。
5. **アクセシビリティを落とさない。** 現在の `role="img"` + `aria-label` を維持する（装飾は `aria-hidden`）。
6. **EPUB へ転用できるか**を各案で明記する（同じ規則で生成表紙を作れるか）。

## 3. 意匠の案 — 8案

### C-1. Spine（背表紙）— タイトルを主役にする

- **絵**: 面いっぱいにタイトル。文字数に応じて 3 段階（〜12 字は大、〜30 字は中、それ以上は小＋4 行クランプ）。下端に作者名を 1 行、上端に提供元の細帯。
- **なぜ効くか**: P1・P2 を同時に解く。棚に並んだ背表紙と同じ原理で、**見分けの情報＝タイトルそのもの**を絵にする。
- **実装**:

```tsx
const scale = work.title.length <= 12 ? "lg" : work.title.length <= 30 ? "md" : "sm";
<Box className="work-cover__empty" data-scale={scale} …>
```
```css
.work-cover__empty-title { font-weight: 700; line-height: 1.35; word-break: auto-phrase; }
.work-cover__empty[data-scale="lg"] .work-cover__empty-title { font-size: clamp(13px, 15cqi, 22px); }
.work-cover--compact .work-cover__empty-title { display: none; }  /* 46px では帯とアイコンだけ */
```
- **compact**: タイトルは出さず、提供元の帯＋種別の頭文字1字。
- **EPUB 転用**: 可（XHTML+CSS の扉としてそのまま作れる。文字だけなので画像生成が不要）。
- **コスト**: 小

### C-2. Deterministic Hue（作者で色が決まる）

- **絵**: 背景色を**作者 ID のハッシュ**から決める。同じ作者の作品は同じ色になり、棚が作者ごとに固まって見える。前面には作者名の頭 1 文字（日本語なら 1 文字、英字なら 2 文字）。
- **なぜ効くか**: P1 を解きつつ、FANBOX のように「作者単位で読む」使い方に噛み合う。
- **実装**:

```ts
/** 同じ入力からは必ず同じ色。彩度と明度は固定し、色相だけを配る。 */
export function accentHue(seed: string): number {
  let hash = 0;
  for (const ch of seed) hash = (hash * 31 + ch.codePointAt(0)!) % 360_000;
  return hash % 360;
}
```
```css
.work-cover__empty { background: hsl(var(--seed-hue) 42% 92%); }   /* light */
:root[data-mantine-color-scheme="dark"] .work-cover__empty { background: hsl(var(--seed-hue) 30% 18%); }
```
- **注意**: 色覚特性の差で色相だけでは区別できない利用者がいる。**色は補助**とし、必ず文字（頭文字・タイトル）と併用する。
- **compact**: 色＋頭文字だけで成立する。**最小サイズで最も強い案。**
- **EPUB 転用**: 可（HSL を Rust 側で同じ式から再現できる）。
- **コスト**: 小

### C-3. Manuscript（原稿用紙）— 現状路線の洗練

- **絵**: いまの罫線を、種別で描き分ける。小説＝マス目（20×20 の格子を薄く）、記事＝横罫のみ、画像＝方眼、ファイル＝無地。罫の密度もサイズに応じて変える。
- **なぜ効くか**: P4（効かない `uppercase` ラベル）を、文字ではなく**紙の種類**で表現に置き換える。
- **実装**: `repeating-linear-gradient` を `data-kind` で切り替えるだけ。DOM は増えない。
- **弱点**: 同じ種別どうしはやはり同じ絵になる。**単体では P1 を解かない**ので C-1 か C-2 と併用する。
- **EPUB 転用**: 可（CSS のグラデーションは EPUB でも動くが、古い端末では無視される）。
- **コスト**: 小

### C-4. First Lines（冒頭を敷く）

- **絵**: `excerpt`（または本文冒頭）の最初の数行を、極小・低コントラストで背景に敷き、その上にタイトル。実際の中身が絵になる。
- **なぜ効くか**: P1・P2 を解く上に、「どんな話か」がサムネイルから伝わる。
- **実装**: `summaryText(work.excerpt)` を 120 字で切り、`font-size: 6px; line-height: 1.5; opacity: .35;` でクランプ。`user-select: none`。
- **弱点**: `excerpt` が空の作品がある（FANBOX の画像投稿など）。**フォールバックが必ず要る**（C-1 に落とす）。46px では判読不能なので compact では敷かない。
- **EPUB 転用**: 可だが、扉に本文の断片を出すのは好み次第。
- **コスト**: 中

### C-5. Creator Portrait（作者の顔）

- **絵**: 作者アイコン（`personIconPath`）を大きく敷き、下 1/3 に半透明の帯とタイトル。アイコンが無ければ C-2 に落ちる。
- **なぜ効くか**: FANBOX は「クリエイターを追う」媒体で、実際にアイコンが手元に保存されている（カードの著者行が既に使っている）。
- **弱点**: 同じ作者の投稿は全部同じ絵になる（P1 が半分しか解けない）。連載を並べたときは C-7 と組み合わせる。
- **EPUB 転用**: 可（アイコン画像を表紙に埋め込む。ただし Kindle の推奨は長辺 1200px 以上で、アイコンは小さい）。
- **コスト**: 小

### C-6. Identicon（作品 ID から作る模様）

- **絵**: `source + sourceId` のハッシュから、対称な幾何模様（5×5 の格子、GitHub の identicon と同型）を決定論的に描く。色は C-2 と同じ規則。
- **なぜ効くか**: **すべての作品が確実に違う絵になる**。P1 に対して最も強い。
- **弱点**: 模様に意味が無く、記憶の手がかりが弱い（「どの模様がどの話か」を覚えられない）。抽象度が高く、アプリの静かな一覧に対しては賑やかすぎる可能性。
- **EPUB 転用**: 可（Rust 側で同じハッシュから SVG→PNG を生成できる）。
- **コスト**: 中

### C-7. Episode Number（話数を大書きする）

- **絵**: シリーズ物のとき、`第12話` の「12」を面の中央に大きく置き、上にシリーズ名（小）、下にタイトル（小）。シリーズでなければ公開年月（`2026.05`）を同じ位置に置く。
- **なぜ効くか**: 連載を順に読む使い方に直結する。棚が「順番」で見えるようになる。
- **実装**: `work.seriesTitle` と（あれば）話数。話数はいま `DownloadEntry` に無いため、シリーズ内の並び順から求めるか、`series_order` 相当の追加が要る（要調査）。
- **EPUB 転用**: 可（統合書き出しの部扉と同じ意匠にできる）。
- **コスト**: 中（データの手当てが要る）

### C-8. Brand Plate（提供元の面）

- **絵**: 提供元のブランド面（pixiv＝青地に白ロゴ、FANBOX＝黄地に黒ロゴ）を、面としてしっかり見せる。`BRAND_GLYPHS` の既存グリフを流用。
- **なぜ効くか**: 出所が一目で分かる。実装が最も軽い。
- **弱点**: P1 をまったく解かない（提供元は 2 つしかない）。**現状より悪化する可能性がある**（いまはアクセントが細帯なのに対し、全面が彩色されると一覧が騒がしくなる）。単独では非推奨。
- **EPUB 転用**: 可。
- **コスト**: 極小

## 5. 推奨

**C-1（背表紙）を基本形にし、C-2（作者で色）を下敷き、C-7（話数）を条件付きで重ねる**、という 1 つの意匠に合成する。

```
┌──────────────┐
│▔▔▔▔▔▔▔▔▔▔▔▔▔▔│ 提供元の細帯（現状どおり）
│              │
│  シリーズ名   │ ← あるときだけ（小・muted）
│  タイトル     │ ← 主役。文字数で 3 段階
│              │
│  ● 作者名     │ ← 作者色の点 + 名前
└──────────────┘   背景 = 作者ハッシュの淡い色
```

- `card` / `detail`: 上図のまま。
- `compact`（46〜52px）: 背景色（作者ハッシュ）＋作者頭文字 1 字＋提供元の細帯。**文字は 1 字だけ。**
- `excerpt` も `seriesTitle` も無い作品でも、タイトルと作者名は必ずあるので**フォールバックが不要**。

段階実装:

| 段階 | 内容 | 工数 |
|---|---|---|
| 1 | C-1（タイトル表示 + 3 段階スケール）を `card` に導入。P3 対策で「読む」アイコンを外す | 半日 |
| 2 | C-2（決定論的な色）を追加。`accentHue` を `src/lib/` に置き、テストを書く | 半日 |
| 3 | C-7（話数）を、シリーズ情報がある作品にだけ | 1日（データ調査込み） |

## 6. EPUB の生成表紙への転用（P5 への対応）

現状、`EpubBuilder::build` は次の条件で表紙ページを作る。

```rust
let has_cover_page = settings.include_cover_page && cover.is_some();
```

つまり **表紙画像が無い＝表紙ページが無い**。ここに、カードと同じ規則で作った「生成扉」を入れられる。

### 実装の選択肢

| 方式 | 中身 | 長所 | 短所 |
|---|---|---|---|
| G-1 XHTML の扉 | `cover_page.xhtml` を文字組みで作る（画像なし） | 画像生成が不要。文字が鮮明。テンプレートで自由に変えられる | OPF の `cover-image` が無いままなので、**書架アプリのサムネイルは空のまま** |
| G-2 生成 PNG | 同じ意匠を Rust 側で描き、`OEBPS/images/cover.png` として収録 | 書架のサムネイルにも出る。Kindle の推奨（長辺 1200px 以上）を満たせる | 描画（文字の折返し・フォント）を Rust 側に持つ必要がある |
| G-3 SVG の扉 | SVG で扉を作る | 実装が軽い | **Kindle が苦手**。互換性レポートの方針（既定は単純な `img`）に反する |

**推奨は G-1 を既定にし、G-2 を `template.json` の `generateCoverImage: bool` で選べるようにする。** G-1 だけなら Rust の変更は「`has_cover_page` の条件を `include_cover_page` だけにし、`cover_image_href` が無い場合の分岐をテンプレートに委ねる」に収まる。

```jinja
{# cover_page.xhtml.j2 #}
{%- if cover_image_href %}
<div class="cover-frame"><img src="{{ cover_image_href }}" alt="{{ strings.COVER_TITLE }}" /></div>
{%- else %}
<div class="cover-plate" data-source="{{ provider.source }}">
  {%- if core.isPartOf %}<p class="cover-plate__series">{{ core.isPartOf.name }}</p>{% endif %}
  <h1 class="cover-plate__title">{{ core.name }}</h1>
  <p class="cover-plate__author">{{ core.author.name }}</p>
</div>
{%- endif %}
```

G-2 を採る場合の注意:

- 文字を含む画像は**代替テキスト**（`alt`）に同じ文字列を入れる。
- 日本語フォントを同梱しない（ライセンスと容量）。**システムフォントに依存する描画は再現性が無い**ため、`ab_glyph` などでフォントを指定するか、G-1 に留めるのが現実的。
- 長辺 1200px 以上・JPEG または PNG。既存の `image_processor` をそのまま通せる。
