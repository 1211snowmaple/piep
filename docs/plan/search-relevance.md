# 検索の当たりすぎと、句の検索が落ちること

2026-09-07 の記録。**どちらも 0.19.0 で直した。** 何が起きていたかと、
どう確かめたかを残す。

## 分かったこと（要約）

- **n-gram の欄に句（フレーズ）の検索を投げていた。** n-gram のトークンは位置を
  持たないので、句の意味が消えていた。具体的な語で棚の43%が当たっていた
- **その句の検索が Tantivy の中で落ちていた。** 開発ビルドだけで、配布ビルドでは
  落ちない。ただし前提違反そのものは配布ビルドでも起きていた

二つは無関係ではなかった。落ちるのは句の検索であり、その句が壊れていたのは上の
理由である。**n-gram に位置を振ったら、両方とも消えた。**

## 1. 当たりすぎる

「空倉第一高校異文化交流部」で **4,013 件**（棚 9,370 件の43%）が当たる。

欄ごとに測ると、犯人は一つだけだった。

| 件数 | 欄 | 変種 |
| ---: | --- | --- |
| 4,013 | `body_reading_romaji` | `sora kura dai ichi koukou i bunka kouryuu bu` |
| 16 | `body_reading_kana` | `そら くら だい いち こうこう い ぶんか こうりゅう ぶ` |
| 1 | `excerpt_reading_romaji` | 同上 |

読みの正規化で「空倉第一高校異文化交流部」は空白区切りの読みになる。空白を含む
ので `query_literal` が引用符で包み、Tantivy は**句の検索**として組む。

組まれた句を覗くと、**85 個の語がすべて位置 0 にある。**

```
PhraseQuery { phrase_terms: [(0, "so"), (0, "sor"), (0, "or"), (0, "ora"),
  (0, "ra"), (0, "a "), (0, " k"), (0, " ku"), (0, "ku"), ...], slop: 0 }
```

位置がすべて 0 だと、句は並び順を縛れない。**「この n-gram が全部どこかにある」
だけの条件に化ける。** 2〜3文字のローマ字断片（`so` `or` `ra` `a ` ` k`）は、
ローマ字に開いた日本語の本文ならまず含まれる。だから43%当たる。

かなの欄が 16 件で済むのは、かなの2文字が英字の2文字よりずっと絞り込めるから
であって、仕組みが違うからではない。**同じ壊れ方をしている。**

原因は piep 側にある。`register_tokenizer` が使っている
`NgramTokenizer::all_ngrams(2, 3)` は、Tantivy の説明にこうある。

```
/// With this tokenizer, the `position` is always 0.
```

**位置を持たないトークナイザの欄へ、位置を要る問い合わせを投げている。**

### 直したこと

`PositionedNgramTokenizer` を書いた。出す語と順番は `all_ngrams(2, 3)` と同じで、
**位置だけを 0 から順に振る。** 同じ解析器が索引側と検索側の両方を通るので、
語のトークン列は本文のトークン列の中に連続して現れ、句が隣接を縛るようになる。

索引に書かれている位置の意味が変わるので `INDEX_VERSION_DIR` を v5 から v6 へ
上げた。更新後の初回起動で全件が作り直される（棚 9,370 件で実測 58 秒）。

確かめ方は、**直す前の解析器と並べて走らせる**（`ngram_position_regression`）。
語の並びを回した文を作ると、前後にまたがる断片まで含めて必要な n-gram が全部
そろい、違うのは並びだけになる。

| | 並びだけ違う本文 |
| --- | --- |
| 位置を持たない解析器（直す前） | **当たる** |
| 位置を振った解析器（直したあと） | 当たらない |

棚の実物で作り直して測った結果。

| 検索語 | 直す前 | 直したあと |
| --- | ---: | ---: |
| 空倉第一高校異文化交流部 | 4,013件 | 0件 |
| 空座第一高校 | — | 3件 |
| 異文化交流部 | — | 2件 |
| 松本乱菊 | — | 38件 |
| 食蜂操祈 佐倉愛里 | — | 1件 |
| BLEACH | — | 52件 |

「空倉第一高校異文化交流部」が 0 件になるのは正しい。実際の題は
「空座第一高校 異文化交流部」で、**倉ではなく座**であり、間に空白もある。
題のとおりに引けば 3 件で当たる。

## 2. 句の検索が落ちる

```
target (4194) should be greater than or equal to doc (4461)
```

棚の索引で再現する。`BLEACH 空倉第一高校異文化交流部` のような2語の検索で出る。

呼び出しの連鎖は全部 Tantivy の中である。

```
Intersection::advance
  -> BufferedUnion::seek_danger      ← 子が追い越していても target をそのまま渡す
       -> PhraseScorer::seek_danger  ← 前提違反を検出して落ちる
```

`buffered_union.rs` は子の現在位置を見ずに target を配る。

```rust
for docset in self.docsets.iter_mut() {
    match docset.seek_danger(target) {   // target < docset.doc() でも渡す
```

`DocSet` の**既定の**実装は安全で、追い越していたら何もしない。落ちるのは
既定を上書きしている `PhraseScorer` だけである。

こちら側で包んで避けられないかを当たった。

| 包み | `seek_danger` | 効果 |
| --- | --- | --- |
| `BoostScorer` | 中へ転送 | 効かない（piep は既に field boost を使っている） |
| `ConstScorer` | 上書きしない＝既定 | 効くが点数が定数になり、関連度順が壊れる |

union は `Intersection` の内側にあるので、外側を包んでも届かない。届かせるには
`QueryParser` をやめて問い合わせ木を自前で組むことになる。

実害の切り分け。

| | 開発ビルド | 配布ビルド |
| --- | --- | --- |
| 2語の検索 | **落ちる** | 落ちない（25件返る） |

`debug_assert!` なので配布物では消える。ただし前提違反は配布ビルドでも起きて
いるので、返ってきた 25 件に取りこぼしが無いとは言えなかった。

### これも 1 を直したら消えた

位置が全部 0 の句は、phrase scorer の中で位置の突き合わせが縮退する。1 を直して
索引を作り直したあと、**同じ検索を開発ビルドで走らせても落ちない。**

```
BLEACH 空倉第一高校異文化交流部 -> 0件
空座第一高校 異文化交流部       -> 1件
松本乱菊 BLEACH                 -> 31件
食蜂操祈 佐倉愛里               -> 1件
```

union 側の取り違え自体は Tantivy に残っている。**壊れた句を渡さなくなったので
踏まなくなった**のであって、上流が直ったわけではない。同じ形の句を作れば
また踏みうるので、報告はしておくとよい。

## 索引は壊れていない

作り直しの取りこぼしを疑って測ったが、そちらは健全だった。

```
segments: 13 / 一致した distinct id: 4,013 / 重複して出た id: 0
```

## 測り直し方

使い捨ての example を書いて測った。残していない。同じことをするなら:

- **欄ごとの件数と、組み上がった問い合わせ**を見る。`ensure_index` で索引を開き、
  `query_variants` で変種を作り、欄ごとに
  `QueryParser::for_index(&index, vec![field])` で数える。`Query` は `Debug` を
  実装しているので、句の語と位置がそのまま読める
- **棚の実物で作り直して確かめる。** `VACUUM INTO` で DB を写し、別の保管場所へ
  `Database::open` して `rebuild_search_index` を回すと、本物の棚に触らずに
  新しい索引で検索を試せる。落ちるかどうかは `debug_assert!` なので
  **開発ビルドで**走らせること
