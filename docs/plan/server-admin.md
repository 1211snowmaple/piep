# サーバーの管理画面の続き

管理画面とデスクトップの画面は 0.36.0 で入った。決めたことの理由は `docs/policy/06-backend.md` の「サーバーの管理画面」と `docs/policy/05-frontend.md`、使い方は `docs/guide/05-server.md` にある。ここには、まだ作っていないものだけを残す。

## 携帯の更新（Android 0.5.0）

今はアプリを開いて 24 時間ごとに確認するだけで、通知がない。次を足す。

- WorkManager で 1 日 1 回、裏で確認する
- `POST_NOTIFICATIONS` を、設定の「アプリの更新」で通知を入れるときに求める。起動直後には求めない
- 新しいバージョンがあれば通知を出す。押すとアプリの更新画面を開き、ダウンロードの進み具合を出して、インストールの確認まで進める
- 署名は OS が確かめる。今の固定の URL と `latest-android.json` は変えない
- Android 12 以降の `PackageInstaller` では確認なしの更新ができる場合がある。**実機とエミュレーターで確かめてから決める**
- サーバーのバージョンは、登録済みの端末なら `GET /api/v1/about` で読む（`version`、`apiVersion`、`serverName`、`capabilities`）
- `latest-android.json` に `minServerApi` を足し、携帯の新しいバージョンが要るサーバーを示す

最初の 1 回の APK のインストールと、インストールの許可は OS の決まりで省けない。

## バージョンの組み合わせ

| 組み合わせ | 動き | 状態 |
| --- | --- | --- |
| サーバーがデスクトップより古い、自動更新が入 | サーバーに更新を頼む | 済み |
| サーバーがデスクトップより古い、自動更新が切 | 状況のカードで知らせ、押すまで変えない | 済み |
| サーバーがデスクトップより新しい | デスクトップの更新を案内する | 済み |
| 送信の形式が合わない | 送信だけを止めて理由を出す。読むことは止めない | 形式を変えるときに `syncFormat` を足す |
| 携帯がサーバーより新しい | 携帯に「サーバーを更新してください」。使えない機能は `capabilities` で隠す | Android 0.5.0 |
| 携帯がサーバーより古い | 携帯の更新の通知を出す。読むことは止めない | Android 0.5.0 |

リリースの手順に「Android 版との対応を確かめる」を足す。

## 次の段階

- **TOTP:** 回復コードを発行し、切るコマンドを用意する。管理用のアドレスを外に出さなければ、パスワードだけでも十分な強さがある
- **バックアップと通知の画面:** 保持数と時刻を管理画面で変えられるようにする

## 決めずに残すこと

- パスキー。安定したドメインを持つ人が増えてから考える
- 多人数のアカウント。ライブラリの持ち主だけが使う前提を変えない
- 管理用のアドレスを外に出すための追加の仕組み。出さない前提を変えない
- 外から入るときのプロキシの認証。転送のヘッダーを信じない今の規則を変える話なので、要望が出てから考える
