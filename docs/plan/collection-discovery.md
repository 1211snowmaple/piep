# まとまりの発見

## 目的と適用範囲

**最優先は、読む単位として整理されていない連続物を見つけ、読む順を確認して保存できること。**
公式シリーズ未登録、リクエスト集などのシリーズ内に埋もれた前後編、pixivとFANBOXに
分かれた続き物を、最初から対象に含める。シリーズ所属や投稿サービスを探索の境界にしない。
候補の総数やテーマの多様さは、この目的を満たしたあとで改善する。
同じ話の続編、同じ世界の独立作、同じ題材の作品、別版を区別する。

この文書は採用する設計方針を定める。「現行実装」以外の節は今後の実装要件であり、
実装済みの機能を説明するものではない。実装の完了に合わせて状態を更新する。
実験の経緯と個別の測定結果はここへ蓄積しない。

## 現行実装

- 棚の走査は本文リンク、題名族、公式シリーズの連番から続き物を作り、タグと本文ベクトルからテーマを作る。
- 版違い・合本の畳み込み、候補どうしの重なりの統合、既存コレクションとの完全一致除外がある。
- 系統ごとに最大8件を強さに重みを付けて抽選する。受信箱の既定は全系統で、候補の点数順に並ぶ。
- 候補画面には題名、作者、字数、束全体の根拠を出す。作品の選択と名前案の選択ができる。
- 採用は新しいコレクションを作る。候補段階で順序を編集する操作はなく、採用後に並べ替える。
- 保留操作と窓を閉じる操作は候補の下書きを削除する。採否の一部は作品ペアとして記録する。
- 全作品を種とする走査候補の部分却下は、選択外の種とのペアも拒否し得る。画面の説明と一致していない。

実装の入口は [走査](../../src-tauri/src/database/queries/collection_sweep.rs)、
[採否の保存](../../src-tauri/src/database/queries/collections.rs)、
[候補の確認](../../src/features/collections/SuggestionInbox.tsx)。

## 優先順位

| 優先度 | 扱う問題 | 後回しにするもの |
|---|---|---|
| P0 | 未登録・シリーズ内部・サービス跨ぎの正解集、取りこぼし、版と合本、誤結合、階層順序、拒否範囲の不整合 | テーマの件数増加、命名の改善 |
| P1 | 表記ゆれの拡張、既存束の補完、根拠確認、保留と修正の記録 | 全作者・全作品へ高価な推論をかけること |
| P2 | タイトルの異なる弱い続編、任意のモデル判定、テーマの多様性 | 評価を通らない自動統合 |

「未整理」を、シリーズ情報なし、別シリーズへの分断、シリーズ内部の小さな連続物に分ける。
管理用の名前かどうかは集計用の補助情報とする。普通の名前のシリーズにも複数の物語が入り得る。
すでに物語単位で整理された公式シリーズは比較対照とする。公式シリーズの有無だけで
一律に除外せず、今回の発見で利用者の整理が増えるかを優先順位へ反映する。

## 投稿と読む単位を分ける

公式シリーズは取得元の入れ物、投稿は保存した原本、読む単位は作品どうしの関係から作る下書きである。
一つの投稿が複数話を含み、同じ話が複数の投稿に現れるため、一投稿を一話と決めつけない。

| 場面 | 保持する関係 |
|---|---|
| リクエスト集にA前編・A後編・B前編・B後編 | AとBを別の読む単位にする。入れ物の全作品へ所属を広げない |
| pixivのA前編、FANBOXのA後編 | サービス境界を越える続編の辺 |
| pixivのA合本、FANBOXのA①・A②・A③ | 合本の包含と分冊の読む順。合本を第0話にしない |
| 無料抜粋、完全版、再掲 | 同じ話の別版候補。分量が多いだけで確定しない |
| 第1章前編・第1章後編・第2章前編 | 種類を持つ階層順序。単一の整数へ潰さない |

原本のIDを保ち、版の同一性・抜粋・包含は根拠付きの関係として別に持つ。
表示上の代表を変えても、元の投稿にあったリンク・シリーズ所属・本文位置を失わない。
合本と分冊は代替の読み方として確認に出し、同じ本文を二度読む順序を自動確定しない。
本文包含は両方向に測る。一方向だけ重なる場合は、同一版より抜粋・合本を疑う。
有料部分が未保存の場合は本文不足とし、タイトルだけで包含を決めない。

作者の対応は取得元内ID、確認済み別名、相互のプロフィール参照等を証拠として持つ。
表示名の一致は跨サービスの候補生成に使えるが、同名の別人や同作者の独立作も残る。
表示名が異なる場合でも明示的な作品リンクから比較できるようにする。

## 四段階に分ける

### 1. 候補ペアを広く集める — candidate generation

この段階で決めるのは「比較する価値があるか」だけで、束への所属は決めない。
次の入口を併用し、どの入口が拾い、どこで落ちたかを記録する。

- 明示された前編・続編リンクと、そのアンカー、近傍文、リンクのある本文位置。
- 作者ごとの題名検索。話数、章、前後編、括弧、丸数字、表記ゆれを構造として取り出す。
- `【サンプル】（後編）作品名` の配布注記と本題を分け、`後編①／後編②` の階層を残す。
- 題名の部分一致、文字n-gram、低頻度語の一致。固定長の先頭一致だけに閉じない。
- 本文中の作品名参照、前回への言及、登場人物・舞台の継続。本文取得済みの範囲を明記する。
- 作者と公開時期の近傍、任意の意味検索。これら単独では連続物と認定しない。

版を消す前に同一作品の候補関係を保持する。別版のリンクが持つ続編情報も原作品へ引き継ぐ。
作者IDは取得元ごとに扱い、表示名一致だけで同一人物を確定しない。
未保存のリンク先は欠落の証拠として保持し、存在しない本文や話数を補わない。

### 2. 関係を分類する — relation classification

ペアごとに `続編 / 同じ連作の独立作 / 別版 / 合本が含む作品 / 関連・宣伝 / 無関係 / 不明` を判定する。
続編は向きを持ち、前後編や章の階層、分岐、欠番を別の情報として持つ。
関係の根拠と向きの根拠は分け、出典と実際の文字列を確認できるようにする。

共通タグ、同一作者、本文類似、同じ公式シリーズへの所属は補助情報である。
リンクも無条件には強い証拠にしない。全記事共通の案内、依頼置き場、宣伝リンク、
別版への誘導と物語の続編リンクを分類する。リンク数だけで本文の濃いハブを信用しない。
互いに矛盾する強い根拠があれば「不明」に残す。点数を足して矛盾を隠さない。

### 3. 制約付きの有向グループを作る — constrained directed grouping

続編の辺から束を作る。つながった成分をそのまま一つの束にしない。
弱い1辺が二つの物語を橋渡ししたときは、その辺の根拠を再確認する。
既存の強い小集団を、題名やタグの近さだけで合併しない。

- 版違いと合本の包含関係を、続編の辺へ変換しない。
- 章をまたぐ同じ話数、複数の前編、分岐は別の節として保持する。
- 循環、前後関係の矛盾、根拠のない飛び越しを検出し、勝手に投稿日で解消しない。
- 向きが確かな部分だけを並べ、残りは順序未確定として確認へ送る。
- 件数上限を超えた連作は捨てず、境界を説明できる章・区間へ分割する。
- 統合・分割・版の代表変更後に、所属と順序の根拠を最終構成で再計算する。

候補の強さ、未整理としての価値、確認負担、既視感を別に持つ。
公式シリーズと同じ顔ぶれを見つけることと、埋もれた前後編を発見することを同じ点数で競わせない。

### 4. 発見から採用までをつなぐ — review flow

既定は未整理の続き物。まず根拠の強い未確認候補を出し、探索枠は少数に限定する。
「次の候補」と「棚の再解析」を分け、同じ入力で見た候補を何度も引き直させない。
テーマは別の入口として残す。

候補詳細では、提案順、作品ごとのリンク抜粋と根拠、欠番、順序未確定、別版を確認できるようにする。
本文を開いて戻っても選択と順序を保つ。採用前に作品の除外と順序修正ができるようにする。
既存束との重なりは「共通の作品・増える作品」を示し、新規作成と既存束への追加を選べるようにする。
一部が重なる候補を一律に削除しない。同じ作品を複数の束へ入れる用途は維持する。

候補には内容に基づく安定した識別子と規則・入力の版を持たせる。
`未確認 / 確認済み / 保留 / 採用 / 明示的な却下` と、作品・順序の修正を区別して記録する。
閉じること、読まなかったこと、採用時に作品を外すことだけでは、恒久的な負例にしない。
却下は対象のペア・集合・関係を明示し、選択外の作品へ広げない。判断を取り消す経路も用意する。
規則を更新しても利用者の判断の履歴を消さず、再評価した理由を保持する。

## 評価と採用条件

### 正解集を先に固定する

旧Python候補、既存公式シリーズ、採用済みコレクションは正解集の材料であり、正解そのものではない。
これらの候補からの標本に加え、作者の全作品を読んで探す標本を用意し、検出器が見逃した連続物も含める。
未整理の三層、整理済みシリーズ、跨サービス、欠番、無番号、階層話数、別版、合本、宣伝ハブを含める。
同じ作者・人物・題材・公開時期だが別作品の組を、難しい負例として独立に集める。

各例に作品の同一性、ペア関係、正しい束、既知の順序、根拠、判定者、保留理由を付ける。
真の不明例を負例へ入れない。意見が割れた例は再確認し、判断不能なら採用判定用の分母から分離する。
別版と転載を同じ原作品へ対応付け、作者単位で調整用・検証用・固定テストへ分ける。
同じ作者の別名、同じ連載、転載が別の分割へ漏れないようグループとして固定する。
既知シリーズの情報を隠す評価は補助実験に留め、実際の未整理作品の評価を置き換えない。

### 生成・結合・提示を別々に測る

| 段階 | 必須指標 |
|---|---|
| 生成 | 正解続編ペアの再現率、作者ごとの候補数、層ごとの取りこぼし理由 |
| 分類 | 続編の適合率・再現率、別版／宣伝／同題材との混同、方向の正解率、不明率 |
| 結合 | 束の完全一致率、所属の適合率・再現率、分裂率、順序制約違反率 |
| 誤った橋 | 異なる正解連作を結ぶ誤辺数、誤結合した束の割合、その誤辺によって誤所属した作品数 |
| 提示 | 初回8件の適合率、10回までの累積新規発見数、再提示率、1採用あたりの確認時間 |
| 採用後 | メンバーと順序の修正率、重複作成率、既存束へ補完できた正解作品数 |

大きな連載が平均を支配しないよう、作品・作者・連作それぞれの集計を報告する。
全候補を決定論的に評価したあと、乱数種を固定した複数回の提示評価を行う。
「候補が増えた」「3回とも読めそうだった」だけを改善の根拠にしない。
同じ確認予算で未整理連続物の再現率が上がり、適合率と誤った橋の被害が悪化しない変更を採る。
正解数と区間推定を併記し、差を判断できないときは正解例を増やして再評価する。

### 1万作品で実行時間を測る

最低1万作品、偏った多作作者、長文、リンクハブを含む棚で全走査を計測する。
本文・意味索引は取得済みの条件とし、モデル取得・索引作成の時間は別に測る。
起動直後と2回目以降を分け、同じ環境で各20回以上のp50・p95、ピークメモリ、候補ペア数を記録する。
初期の性能予算は、ルールによる全走査のp95を5秒以内とする。これは目標であり達成済みの実測値ではない。
意味・モデル判定を追加する場合は別の時間予算を決め、通常の続き物候補の返却を待たせない。
索引なしでもルール経路は完了し、候補なし・未処理・処理失敗を区別する。
性能予算を外れる変更は有効性を確認しても通常経路へ入れず、候補生成の絞り込み・差分更新を先に行う。

## 棄却する仮説と実験の扱い

- 「同じ作者＋同じシリーズ／タグなら続き物」：管理用シリーズと難しい負例で破れるため、単独の採用条件にしない。
- 「リンクでつながれば同じ連載」：宣伝と別版の辺が橋になるため、分類なしの連結成分を採らない。
- 「長い共通語幹や大きい束ほど確か」：無番号の題名テンプレートと独立短編を混同するため、所属証拠としない。
- 「投稿日順で読む順を直せる」：転載、再掲、章の前後編で破れるため、順序の矛盾を消す処理にしない。
- 「意味が近い／モデルがそう答えたら続編」：題材の近さと連続性を混同するため、独立した検証なしで束を作らない。
- 「候補を抽選し直せば取りこぼしは解消する」：生成されない候補には届かないため、生成の再現率改善と分ける。

新しいアルゴリズムは積極的に比較する。入口を一つずつ加える比較、根拠を外す比較、
作者を跨ぐ検証を行い、改善がどこから来たかを確認する。負けた仮説も理由を実験記録へ残す。
既存の閾値だけを調整し続けず、データ欠落、正規化、関係分類、結合のどの段階が原因かを先に特定する。

比較用の道具は [sequence-research](../../tools/sequence-research/README.md) に置く。
構造化した題名解析、文字n-gram、URL局所分類、関係別グラフ、本文包含を個別に比較する。
新たな手法は別の入口として試し、失敗例を直した開発結果と独立した評価結果を分ける。

## 既存方針との境界

[データ](04-data.md)の「原本を保つ」「利用者が所属と順序を決める」「版を続きとして重複させない」は維持する。
同文書の以下の記述は、この方針に沿う実装時に同じ変更で更新する。

- 「束の証拠がなければ候補にしない」は、広く集める候補ペアと、採用を勧める束を区別する記述へ改める。
- 「本文リンク／公式の隣接話数」は、関係の種類と根拠を検証したときに限り続編の証拠とする。
- 三系統は利用上の区別として維持するが、続き物とテーマを同じ優先度で提示しない。
- 「表示名で同一作者を突き合わせる」は候補生成に限定し、人物や原作品の同一性の確定条件にしない。
- 「300件」「系統ごとに閉じる」は現行と一致しない。確認状態と保留・却下の契約を実装に合わせて置き換える。
- `collection_pair_feedback` だけで所属・順序の判断を覚えられるとは扱わず、対象と判断の履歴を明確にする。
