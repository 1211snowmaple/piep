# サーバー

**本棚を携帯で読むときは、いつも一つの単独サーバー（`piep-server`）を通す。** デスクトップ版が棚の
写しを送り、サーバーがそれを携帯へ配る。使い方は [サーバーの使い方](../guide/05-server.md)、携帯との
口は [携帯の契約](../../android/PROTOCOL.md) にある。まだ作っていない段階（スナップショット・通知・
本拠化・定期更新）は [サーバーモード](../plan/server-mode.md) にある。

## 一般性

piep は配布するアプリなので、**特定の家の構成を前提にしない。** 単独サーバーに要るのは二つだけ。

- Windows の機械で `piep-server.exe` が動くこと
- その機械に、デスクトップ版と携帯から HTTPS で届く URL があること

URL の作り方は利用者が選ぶ（トンネル、リバースプロキシ、サーバー自身の TLS）。piep は特定の製品を
検出も実行もしない。共有フォルダー・VPN・特定のドメインは要らない。

デスクトップ版では設定の「サーバー（β）」に現れ、入れるまで何も動かない。API と保存の形は、β の間は
予告して変えてよい。

## 役割と認証

| 役割 | だれ | できること |
| --- | --- | --- |
| 管理者 | デスクトップ版（1 台） | 棚の送信、携帯の登録文字列の発行、端末の一覧・解除、状態の確認、サーバーの更新、読み手と同じ読み取り |
| 読み手 | 携帯（最大 16 台） | 読み取りの API、自分の読書位置の読み書き、お気に入りの付け外し |
| 無認証 | だれでも | `GET /api/hello`、`POST /api/pair` だけ |

鍵はすべて暗号学的な乱数の 256 ビット。サーバーは SHA-256 だけを持ち、定数時間で比べる。鍵と登録文字列は
記録に出さない。デスクトップ版は管理者の鍵を Windows の資格情報マネージャーに置く。

### 最初のつなぎ方

1. サーバーで `piep-server install`（または `init --data <置き場>`）を動かす。設定を作り、**管理者用の登録文字列**を
   その場の画面にだけ出す。有効期限は 30 分で、一度だけ使える。出し直すのは `piep-server admin-pair` で、
   管理者がすでにいるときは `--replace` が要る（前の管理者の鍵は新しい登録の時点で失効する）
2. デスクトップ版の「設定 → サーバー（β）」に貼る
3. 携帯の登録と解除はデスクトップ版から行う。「携帯を追加」で、サーバーが 10 分だけ有効な一回限りの登録文字列を
   返し、デスクトップ版はそれを QR と文字列で見せる。解除はすぐ効く（401）

管理者は、読み手と別の URL で登録してよい（携帯は公開の URL、デスクトップ版は家の中の URL など）。初めての送信は
数十 GB になりうるので、速い経路で送れるように。

登録文字列は `{"version": 2, "role": "reader"|"admin", "url": "https://…/", "secret": "…", "fingerprint": null}`。
`url` は任意の `https://` のホスト名か IP で、ポートとパスの前置きを持てる。利用者名・問い合わせ・断片は持てない。
`fingerprint` があればその証明書に固定し（自己署名のとき）、無ければ OS が信頼する CA でホスト名まで検証する。

### インターネットに出す前提での守り

公開した URL は証明書の透明性ログから見つかる。そのため **URL が知られていても読めない**ことを前提に決める。

- 無認証で答えるのは `hello` と `pair` だけ。`hello` は版・サーバー名・機能だけを返し、作品数や棚の名前は返さない。
  アプリの版は、管理者の鍵を持つ相手にだけ `GET /api/admin/status` で返す（古い版だと分かると狙われるため）
- `pair` の鍵は 256 ビットで、期限付き・一回限りなので、総当たりは成り立たない。回数の制限（サーバー全体で 1 分に
  10 回）は負荷を抑えるためのもの。間違った鍵からはどの登録文字列を狙ったのか分からないので、失敗を数えて登録文字列を
  失効させることはしない（他人が失敗を重ねて登録を妨げられてしまう）。失敗の理由は区別せず、すべて 401
- 要求の大きさに上限を置く（JSON は 64 KiB）。遅い要求は時間で切る。認証と管理者の権限の検査は本文を読む前に行い、
  未登録の端末や読み手に管理用の受信枠を使わせない
- 応答に `Cache-Control: private, no-store` を付け（棚の部分を除く。[携帯の契約](../../android/PROTOCOL.md)）、CORS は
  有効にしない。誤りは `{code, message}` だけを返し、パスや内部の誤りの文は返さない
- 平文の HTTP は **127.0.0.1 でしか待ち受けない。** ほかのアドレスでは、サーバー自身の TLS（自己署名か証明書ファイル）を
  必須にする
- 記録には、口の型・状態・所要時間だけを残す。鍵・登録文字列・検索語・本文・作品 ID は残さない
- トンネルやプロキシが付ける利用者名のヘッダーは、認証にも記録にも使わない

**読み手の口と管理の口を分けられる。** `server.toml` に `admin_listen` を書くと、`listen` 側は管理の口に 404 を返す。
書かなければ同じ口で両方を受ける。外へ出す人には分けることを勧める。

## サーバーの作り

`piep-server` は WebView を持たない常駐のプログラムで、本体は `piep_lib::server::standalone` にあり、デスクトップ版と
同じ棚の読み方を使う。検索・本文・目次・コレクションの結果がデスクトップ版とずれないことが、この形にした理由である。
入口は `src-tauri/examples/piep-server.rs` に置き、`cargo build --release --example piep-server` で組む（`src/bin` に
置くと Tauri がデスクトップ版のインストーラーへ同梱してしまう）。

| コマンド | 何をする |
| --- | --- |
| `piep-server install` | 置き場所と出し方を尋ね、起動時に動くよう登録して動かす。引数なしで開いたときもこれ |
| `piep-server uninstall` | 登録を消して止める。置き場所は消さない |
| `piep-server init --data <dir>` | 置き場と設定を作り、管理者用の登録文字列を出す |
| `piep-server serve --data <dir>` | 見張り役として本体を起動し、落ちたら立ち上げ直し、更新を当てる（`install` を通していなければ本体を直接動かす） |
| `piep-server admin-pair --data <dir> [--replace]` | 管理者用の登録文字列を出し直す |
| `piep-server status --data <dir>` | 状態を出す |
| `piep-server stage-library`・`activate-library` | 手で運んだ棚の写しを置いて選ぶ（下の「手で写しを置く」） |

置き場（`<dir>`）:

```text
server.toml              設定（deny_unknown_fields で読む）
piep-server.exe          固定の入口（見張り役）
versions\<版>\           本体の実行ファイル（今の版と直前の版）
shelf\                   手で置いた棚（世代を選んでいないとき）
shelf-generations\       送られた棚の世代（<UUID>\。server.toml の shelf.generation が選ぶ）
shelf-incoming\          受け取り中の棚の実体と台帳
shelf-database-parts\    前に受け取った台帳の部分
shelf-pending.json       切り替えを予約した送信 ID・棚の UUID・引き継ぎ元・切り替え先の世代・作品数
shelf-shipment-results\  確定を受けた印と公開の結果（送信 ID ごと）
state\                   端末などのサーバーの記録（state.db）、証明書、実行の記録
```

## 携帯からの書き込み

携帯が本棚へ書けるのは、読書位置とお気に入りだけ。口の形は [携帯の契約](../../android/PROTOCOL.md) の「書く口」。

- 携帯の変更は配信中の棚の台帳に記録し、デスクトップ版が取り込むまで入れ替えのたびに当て直す
- 読書位置を書き込む前に、要求の利用者と同期世代を認証結果と配信中の棚に照合する。作品の掲載状態と、指定された版・編集の本文に位置があることも確かめる
- デスクトップ版が取り込むのは、写しを作る前だけ。取り込んだ変更が送る写しに入っていなければ、サーバーの記録を消せない

## 棚を配る

単独サーバーは、デスクトップ版から送られた棚の写しを携帯へ配る。携帯が読む口は
[携帯の契約](../../android/PROTOCOL.md) にある。

`server.toml` の `[shelf]` に、棚の UUID（`library_id`）・同期の世代（`sync_epoch`）・配る写しの世代
（`generation`）を置き、`[shelf.readers]` で端末の登録 ID を読む利用者（棚の持ち主）へ明示的に結ぶ。
端末の UUID を利用者の UUID と読まない。登録が有効かは要求ごとに確かめる。読書の bundle・資産の manifest・chunk を返す前に、版と資産の所属に加え、作品がいま棚に載っていることを要求ごとに確かめる。棚から外した作品は、保存版や資産の識別子が分かっていても 404 を返す（同じ chunk を共有する別の作品は、その作品の版から読める）。`[shelf]` を省いた設定では棚を
配らず、登録と管理の口だけで動く。管理の状態の応答（`/api/admin/status` の `shelf`）は、配っている棚の
UUID・同期の世代・作品数（十進の文字列）を返す。管理の口に入る権限と、棚を読む端末の許可は別々に確かめる。
携帯ごとの許可はデスクトップ版の設定から `PUT /api/admin/devices/{id}/shelf` で付け外しし、`server.toml` に
書いて、配っている棚にもすぐ効かせる。解除した端末の許可は消す。

携帯は、端末の「続きを読む」と読了の一覧を、配信応答で確かめた棚と利用者の UUID の組で引く。
同じ URL で棚や読み手が替われば、表示する読書記録も切り替える。

### 送り方

デスクトップ版の「今すぐ送る」と自動の送信は、管理者の鍵で次の口を使う。

| 口 | 用途 |
| --- | --- |
| `GET /api/admin/shelf/shipments` | 受け取り全体の状態と、このサーバーが扱える棚の台帳の版（`schema`）、送信 ID ごとの結果に対応する印（`publicationById`）。デスクトップ版は写しを作る前に対応を確認し、必要ならサーバーの更新を頼む |
| `POST /api/admin/shelf/shipments` | `{libraryId}` で受け取りを始めて `shipmentId` を返す。同じ棚の未確定の受け取りが残っていれば続ける。組み立てや公開を待っている間と、別の棚を配っている場合は 409 |
| `GET …/shipments/{id}` | 指定した送信の `shipmentId` と状態を返す。受け取り中の `receiving`、組み立て中の `assembling`、公開待ちの `pending`、公開済みの `published`、拒否の `rejected` がある。公開済みなら同期の世代（`syncEpoch`）と作品数（`works`）、拒否なら理由（`reason`）も返す。知らない ID は 404 |
| `POST …/shipments/{id}/needed` | `{chunks:[{id,length}]}`（一度に 4096 まで）のうち、まだ持っていない実体を返す |
| `PUT …/shipments/{id}/chunks/{chunk}?length=` | 実体を一つ、保管の形のまま受け取り、識別子と照らす |
| `POST …/shipments/{id}/commit` | `{database}`（台帳の写しの部分の並び）で確定する。202 を返し、別のスレッドで組む |
| `DELETE …/shipments/{id}` | 受け取りをやめて、受け取ったものを捨てる |

- 送り手は台帳を読み取りの接続から一度に写し、台帳が指す実体の一覧を出す。台帳の写しも保管と同じ 4 MiB の
  部分に分けて同じ口で送る。写しは頁の並びを保つので、前に送った台帳と同じ部分は送らない。台帳は先に識別子
  だけを求め、受け手が求めた部分だけを写しから読み直して符号化する
- 受け手は、受け取った実体・前に受け取った台帳の部分（`shelf-database-parts/`）・いま配っている棚の実体に
  無いものだけを求める
- 確定すると、台帳を部分から組み直して全体のハッシュを確かめ、新しい世代（`shelf-generations/<UUID>/`）に、
  いま配っている棚の実体をハードリンクで共有して棚を組み、検査してから置く。読み直すのは、新しく受け取った
  実体を含むファイルと、配っている棚と構成の違うファイルだけ
- 組み終えたら次の起動でその世代を配るよう予約し、見張り役のいるサーバーは自分で立ち上げ直す（いなければ
  手で。そのあいだ `status` に `shelfPending: true` が付く）
- 受け取りは一度に一つ。確定の前に途中で切れても、同じ棚なら受け取った実体を残して続きから受ける。
  確定を受けた ID は別の写しに使い回さない
- 起動のときは、予約に記した引き継ぎ元から読書位置とお気に入りを切り替え先へ写し終えてから、
  `server.toml` の配信先と同期の世代を一度に切り替える
- 引き継ぎが途中で止まったら予約を保持し、次の起動で同じ棚どうしの引き継ぎをやり直す。
  同じ値は重ねて書かない。切り替え済みなら公開結果の記録から再開し、予約を消す前に結果を確定する。
  組み立ての失敗や中断、受け取りの取り消し、引き継ぎ元の変更で公開を断ったときも、送信 ID ごとに理由を記録する
- 棚の写しは今と一つ前の世代を残す。公開や拒否の結果は棚の世代を片付けても残る。デスクトップ版は
  自分の送信 ID の `published` を確かめた時点で送信を成功とする

**携帯とデスクトップの変更が同じ作品で重なったかは、時計ではなく棚の変更の記録で決める。** ほかの写しから
写した変更と、自分で変えた変更を、要求 ID の種類で見分ける。デスクトップが最後に配られた写しを送ってから
（記録の番号で）その作品を自分で変えていなければ、携帯の値にする。両方で変えたときだけ、読書位置は書いた
時刻の新しいほう、お気に入りはデスクトップの値を残す。デスクトップは公開結果の同期の世代と写しの番号を
組で覚えておき、携帯の変更を読む応答の世代が一致するときにその番号を使う。

### 手で写しを置く

`piep-library backup <棚> <新しい出力先>` で作った写しをサーバーへ運び、次のようにする。

```text
piep-server stage-library --data <サーバーの置き場> --shelf <運んだ棚の写し>
piep-server activate-library --data <サーバーの置き場> --generation <準備で表示された UUID>
```

準備は動いているあいだにもできる。検証した写しを `shelf-generations/<準備の UUID>/` に置く。サーバーを
止めて選んだ写しを有効にすると、検証し直してから `server.toml` の `shelf.generation` を書き換える。同じ棚の
写しの切り替えと復元では端末の許可を引き継ぎ、そのたびに同期の世代を新しくする（同じ写しを続けて選んだ
ときは今の世代のまま）。前の写しへ戻すには、止めている間にその準備の UUID を選んで起動する。
送信で切り替えを予約した世代を配るときは、サーバーを起動して携帯の変更を引き継ぐ。

## サーバーの管理画面

管理 API は本文を読み始める前に管理者の鍵またはセッションを確かめる。Cookie の
要求では、その前に Host と Origin も検査する。ログインや初期設定の一度きりの券を
受け取る入口は別に扱う。管理者の登録文字列を再発行したら以前の未使用文字列を失効
させ、登録が成功した時点でも残りを消す。登録済みの管理者は成功するまで有効にする。

作者内シリーズのカーソルは、開いている DB の識別子と SQLite の変更番号を組にして
持つ。本棚の差し替えで DB を開き直すときも、以前の並び順の続きとして受け付けない。
挿絵の変換枠は HTTP の待ち時間ではなく実際の変換処理が終わるまで保持し、要求の
中断で同時変換数の上限が外れないようにする。

携帯に渡す本文では、実際の HTML 属性にあるローカル画像参照だけを作品の画像 ID に
置き換える。解決できない属性はエラーにするが、本文や説明文にある同じ単語は残す。

管理は URL で開くブラウザの画面に置き、デスクトップ版には日々の操作だけを残す。音楽サーバーなど、常時動かす製品の形に合わせるため。
公開用のアドレスには載せず、`admin_listen` か公開 URL のないサーバーでだけ出す。

### ログイン

- パスワードは Argon2id で持つ。下限は 15 文字で、構成の規則は設けず、よくある語と繰り返しだけを断る。長さが強さを決めるから
- 失敗の数え方はアカウント単位の 1 つ。5 回で 1 分待たせ、倍に延ばして 15 分で止める。接続元ごとに数えると、抜け道が増えるだけになる
- Cookie は `__Host-`、`Secure`、`HttpOnly`、`SameSite=Strict`。無操作 30 分か 12 時間で切れ、裏の読み直しは操作に数えない
- 大事な操作（更新の巻き戻し、パスワードの変更、管理者の入れ替え、管理画面の停止）は、5 分以内の入力を求める。リンクで入っただけでは通さない
- コマンドやデスクトップ版から渡すリンクは一度きりで、券はアドレスの `#` の後ろに置く。サーバーの記録と転送元に残さないため

### 別のサイトからの要求

- 変更の要求は `Sec-Fetch-Site` と `Origin` で同じ出どころだけを通す
- `Host` は `127.0.0.1` などのほかは、リンクを発行したときの名前だけを覚えて通す。設定を増やさず DNS の差し替えを防ぐ。ブラウザで知らない名前を開いたときは、JSON ではなく理由と開き方のページを返す（外の資産は読まない）
- CSP は `default-src 'none'` から必要な分だけ開く。インラインのスクリプトを使わず、画面は外の資産を読まない

### 置き場所

- 画面の出力は `piep-server` だけに埋め込む。`PIEP_REQUIRE_ADMIN_UI` を付けて組むと、空のときに失敗する
- サーバーの名前と管理画面の入切は状態の DB に置く。`server.toml` は `deny_unknown_fields` で読むので、キーを足すと前のバージョンへ戻せなくなる
- 見た目は本体の `app.css`、`PiepLockup`、`NavLink` を共有する。別の画面でも piep だと分かるようにするため

### 更新

- 履歴は本体だけが書く。古い監視役が履歴を落とさないようにするため
- 自動を切っても確認は続け、取得と適用だけを止める
- 手で戻すときは、更新の直前に控えた DB も戻す。新しいバージョンで書いた DB を古いバージョンで開かないため

## 導入と更新

目標はデスクトップ版と同じ手間にすること。利用者の手作業として残るのは、サーバーを外へ出す手段（トンネルや
リバースプロキシ）を用意することと、Android の「提供元不明のアプリ」の許可（最初の一回）と更新ごとの OS の確認だけ。

| | 導入 | 更新 |
| --- | --- | --- |
| デスクトップ版 | インストーラーを開く | 案内に従う |
| 単独サーバー | zip を展開して `piep-server.exe` を開き、質問に答える | 自動。デスクトップ版からも頼める |

### 配布物

リリースに `piep-server-<版>-windows-x64.zip`（`piep-server.exe` と VC++ ランタイムの DLL 4 つ）、その `.sig`、
`latest-server.json`（`{"version", "url", "signature"}`）を載せる。署名はデスクトップ版と同じ鍵。VC++ ランタイムの
入っていない機械でも動くよう、DLL を横へ置く。`DirectML.dll` と `d3d12.dll` は Windows に含まれるので同梱しない。
CI は、読み込む DLL が許した一覧の中にあること、空のフォルダーに展開したものが `init` と `serve` で立ち上がって
`hello` に答え、`--version` がタグと一致すること、署名が公開鍵で検証できることを確かめる。

### 入れ方

`piep-server install` が入口である。

1. 管理者の権限が無ければ、UAC で権限を求めて自分を開き直す
2. 置き場所を尋ねる（既定は `C:\ProgramData\piep-server`）。アクセス権は SYSTEM・Administrators・導入した利用者だけに
   する。既存のフォルダーはアクセス権を書き換えずに調べ、ほかの利用者が実行物を変えられる置き場、リンク、祖先から
   差し替えられる置き場は断る。入れ直しでは、古い版の指示や配布元に無い DLL を引き継がない
3. 外からどう届かせるかを尋ねる。トンネルやリバースプロキシの裏なら `listen` は `127.0.0.1:38777` のまま公開の URL を
   尋ね、この機械で直接受けるなら `0.0.0.0:38777` と `tls = "self-signed"` にする
4. 設定を作り、自分と DLL を `versions\<版>\` へ、見張り役を `<置き場>\piep-server.exe` へ写す
5. タスク スケジューラに「起動時に SYSTEM で `serve`」を登録してすぐ動かす。`schtasks /SC ONSTART` の既定は 3 日で
   止めるので、実行時間の制限を外した XML で登録する
6. `hello` が返るのを待ち、管理者用の登録文字列を出す

やり直しても壊さない。設定と棚があれば残し、タスクと実行ファイルだけを入れ直す。質問は引数（`--data`・`--url`・
`--expose`）で飛ばせる。`--no-task` はタスクを登録せず置き場所だけを作る。Linux・Docker は β に含めない。

### 落ちても立ち上がる

`serve` の固定の入口は、起動するたびに今の版の見張り役（`versions\<版>\piep-server.exe watchdog`）へ任せ、見張り役が
本体（同じ exe の `run`）を子として動かす。

- 本体が異常に終わったら、5 秒・30 秒・2 分と間を広げて立ち上げ直す。10 分正常に動いたら間を戻す。5 回続けて
  起動に失敗したら `server_down` を記録し、1 時間ごとに試す
- 更新の最中に固定の入口を名前替え・上書きしない（動いている exe の Windows の制約を避ける）。次の起動で新しい版の
  見張り役を使う
- 新しい版の見張り役を起動できないか異常に終わったら、固定の入口の見張り役で続ける。起動の確認の前に今の版の exe が
  壊れたり消えたりしても、前の版と DB へ戻す道を失わない

### 自分で更新する

- **いつ:** 6 時間ごとに確かめ、新しい版があれば取ってきて検証し、設定の時間帯（既定 03:00〜06:00）に当てる。
  デスクトップ版の「サーバーを今すぐ更新」は時間帯を待たない。デスクトップ版は自分が更新されたあと、サーバーが古ければ
  これを自動で頼む。`auto = false` なら、頼まれたときだけ当てる
- **手順:**
  1. 署名を検証して `versions\<版>\` へ展開し、`--version` が `latest-server.json` の版と一致することを確かめる。
     更新の案内は 64 KiB・30 秒まで、配布物の取得は 30 分で打ち切る。前の展開先に実行ファイルがあっても版だけを
     尋ねて信頼せず、署名済みの配布物から置き直す
  2. 送信が区切りに来るのを待つ（最長 30 分。そのあとは次の時間帯へ延ばす）
  3. DB を整合した形で写す（`VACUUM INTO`）
  4. 見張り役が本体を止め、新しい版を起動する（止まるのは数十秒）
  5. 新しい版が 60 秒以内に `hello` と DB の検査に通らなければ、前の版と写しへ戻し、`update_failed` を記録し、その版を
     飛ばす。待っている印は起動の確認か巻き戻しが済むまで残す。巻き戻しにも印を残し、中断のあとは新しい版を起動し直す
     前に前の版への戻しを終える
- **守り:** 取りに行く先は実行ファイルに固定し、設定や API では変えられない。管理の API が頼めるのは「確かめて当てる」
  だけで、ファイルや URL は渡せない。版を下げるのは上の 5 の戻しのときだけ。古い版を残すのは直前の一つだけ

### Android 版

- **配布物:** 署名した ARM64 の APK と `latest-android.json`（`{"version", "versionCode", "url", "sha256", "size"}`）。
  作る手順は `tools/release.ps1` 一つで、APK の署名・アプリ ID・版を検査してから出す
- **最初の導入:** デスクトップ版の「携帯を追加」に、APK のページへの QR と登録の QR を並べる。登録の QR はアプリの
  カメラで読む（貼り付けも残す）。カメラの権限は読むボタンを押したときだけ求める
- **確かめる:** 起動のとき一日一回と、設定の「更新を確かめる」。取りに行く先は実行ファイルに固定する。新しい版が
  あれば設定とライブラリの上に控えめに知らせ、読書中は割り込まない
- **当てる:** 大きさを示して取ってきて SHA-256 を確かめ、OS のインストーラーへ渡す（`REQUEST_INSTALL_PACKAGES` と
  FileProvider）。本当の守りは OS の検査（同じ署名の鍵で `versionCode` が増えていること）で、SHA-256 は壊れた取得を
  捨てるため。端末に保存した作品と登録は更新で消えない
