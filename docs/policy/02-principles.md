# 設計原則

迷ったときに立ち返る規則。抽象論ではなく、実際に判断を変えたものだけを書く。

## 1. 利用者のライブラリを壊さない

最も強い原則。他のすべてに優先する。

- **原本は書き換えない。** 取り込んだ JSON は `original_json_path` にそのまま残る。
  編集は別リビジョンとして保存され、原本と併存する
- **スキーマ移行は加えるだけ。** `create_schema` はすべてのテーブルを
  `CREATE TABLE IF NOT EXISTS` で作る。どの世代のライブラリでも、一度の冪等な
  適用で現行へ追いつく
- **異物と判定するのは慎重に。** `CORE_TABLES` はデータベースが piep のものだと
  見分けるための指紋であって、アプリが作るテーブルの一覧ではない。ここに新しい
  テーブルを足すと、既存のライブラリがすべて「見知らぬ DB」と判定されて
  退避・初期化される。**この一覧には何も足してはならない**
- **復元は取り込む前に検査する。** バックアップの復元はマニフェストを検証してから
  行う
- **一つのライブラリを一つのプロセスが持つ。** 起動時に助言ロックを取り、二重起動を
  拒む。ロックファイルは終了後も残す（消すと、別プロセスが別の inode を作って
  ロックできてしまう）

## 2. 同じ操作は、どの画面でも同じ結果になる

過去に実際に壊れた原則なので、明文化しておく。

ライブラリの絞り込みが React の state に置かれ、作者ページでは URL に置かれて
いた時期があった。結果として「作品を開いて戻る」と、ライブラリでは絞り込みが
消え、作者ページでは残った。**同じ操作が画面によって違う結果になる**状態だった。

→ [画面の状態はどこに置くか](05-frontend.md#状態をどこに置くか)

## 3. 推測はするが、断定はしない

- 自動生成した候補は下書きとして提示し、確定は利用者が行う
- 保証できないことを保証すると書かない。EPUB は EPUBCheck で検証できる範囲を
  「適合を確認した」と書き、Amazon の非公開な変換処理の結果までは保証しない
- 不具合の原因が推測なら、推測と書く

## 4. 表示する数字は、意味が伝わる数字にする

「10 / 10 件を処理 · 候補 101」という表示があった。数字自体は整合していたが、
「監視対象を10件確認し終えた。そこから候補が101件見つかった」という意味が
伝わらず、しかも自動保存で101件を保存している最中もずっと「10/10（完了）」の
ままだった。

**待機列に入ったものは総数に数える。見つけただけのものは数えない。**
数字を出すときは、それが何の分母と分子なのかを説明できるようにする。

## 5. 大きなライブラリで壊れないことを、実際に確かめる

1万件を超えるライブラリが前提である。

- 一覧は仮想化する（`VirtualizedWorkList` / `VirtualizedEntityGrid`）
- ページ送りでは `placeholderData: keepPreviousData` を使い、取得中に一覧が
  ローディング表示へ差し替わって**ページの高さが縮まない**ようにする。高さが縮むと
  ブラウザが `scrollTop` を切り詰め、読んでいた位置が失われる
- 検索やファセットの取得は、キャッシュの保持時間を用途ごとに変える
  （`src/lib/queryClient.ts`）
- 性能の主張は実測に基づく。診断画面が実データでの検索速度を測れる

## 6. 静かな既定を選ぶ

何も設定していない作品のカードに、橙・緑・オリーブの文字色が並んでいた時期が
あった。20行の一覧で約100個の色付きチップが画面に出ていた。

**色は状態を示すために使い、要素の種類を示すためには使わない。**
「何も設定していない」が視覚的に静かであること。

## 7. コメントには「なぜ」を書く

型と名前から読み取れることは書かない。書くのは、コードを見ても分からないこと
だけである。

```rust
// 良い例（schema.rs より）
/// これは認識のための指紋であって、アプリが作るものの一覧ではない。
/// ここに新しいテーブルを足すと、既存のライブラリがすべて異物に見えて消える。
```

→ [コメントの書き方](10-documentation.md#コメントの書き方)

## 8. 手元が緑でも、CI が緑とは限らない

Node のバージョン差、並列度、ランナーのコア数で結果は変わる。**手元の結果だけを
根拠に「CI も通る」と言わない。** 緑を1回見ただけで「直った」と判断しない。

→ [品質の担保](09-quality.md)
