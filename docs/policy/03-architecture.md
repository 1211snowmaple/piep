# アーキテクチャ

## 全体の形

piep は Tauri 2 のアプリである。ひとつのプロセスの中に、WebView で動く React の
画面と、ネイティブで動く Rust の中身が同居する。

```
┌──────────────────────────────────────────────────────────┐
│ WebView (React 19 / TypeScript / Mantine 9)              │
│                                                          │
│  app/       枠、ルーター、ワークスペース                    │
│  features/  画面ごとの機能                                 │
│  components/ 画面をまたぐ部品                              │
│  services/  invoke の薄い包み ← ここだけが Rust を知る      │
│  lib/       純粋な道具（整形、リンク、色、スクロール）        │
└──────────────────────────────────────────────────────────┘
                          ↓ invoke("名前", 引数)
                          ↑ emit("名前", 値)
┌──────────────────────────────────────────────────────────┐
│ Rust (piep_lib)                                          │
│                                                          │
│  commands/   IPC の入口。薄く保つ                          │
│  database/   SQLite、検索索引、問い合わせ                   │
│  downloader/ 取得と保存                                    │
│  pixiv_api/  pixiv の API クライアント                    │
│  fanbox_api/ FANBOX の API クライアント                    │
│  auth/       認証と WebView2 の操作                        │
│  epub/       EPUB 3.3 の組み立て                           │
└──────────────────────────────────────────────────────────┘
                          ↓
┌──────────────────────────────────────────────────────────┐
│ %APPDATA%\com.hiron.piep\                                │
│   piep.db        メタデータ、タグ、履歴、監視設定           │
│   downloads/     本文 JSON と画像                          │
│   templates/     EPUB テンプレート                         │
└──────────────────────────────────────────────────────────┘
```

## 依存の向き

**上から下へだけ流れる。** 下の層が上の層を知ることはない。

- `features/` は `services/` を呼ぶ。`services/` は `features/` を知らない
- `lib/` は何にも依存しない純粋な道具である。だから単体テストが書きやすい
- `commands/` は `database/` や `epub/` を呼ぶ。逆はない

**`services/` だけが `invoke` を知っている。** 画面のコードに Tauri のコマンド名が
直接現れることはない。名前が変わったときに直す場所を一箇所にするためであり、
Tauri の外（ブラウザでの開発）でモックに差し替えられるようにするためでもある。

→ 実際のコマンド一覧は [IPC コマンド契約](../reference/ipc.md)

## 境界は三つある

フロントと Rust の間には、型検査の効かない継ぎ目が三つある。**どれも文字列で
繋がっているだけで、綴りを間違えれば実行時まで気付かない。**

| 境界 | 数 | 繋ぎ方 | 生成した一覧 |
|---|---:|---|---|
| コマンド | 140 | `invoke("名前")` | [IPC コマンド契約](../reference/ipc.md) |
| イベント | 26箇所 | `emit` / `subscribeTauriEvent` | [イベント契約](../reference/events.md) |
| スキーマ | 28テーブル | SQL の文字列 | [スキーマ](../reference/schema.md) |

この三つはソースから自動で抽出し、**両側の食い違いを CI で検査している**。
フロントが呼ぶ名前の実体が Rust に無ければビルドが落ちる。

→ [検査の中身](09-quality.md#境界のドリフト検査)

## Rust 側の作法

### コマンドは薄く

`commands/` の関数は入口であって、仕事場ではない。実際の処理は `database/`
`epub/` `downloader/` にある。

### DB 作業は専用スレッドへ逃がす

SQLite の操作は同期的で、そのまま async の中で走らせると WebView の応答が
止まる。`run_db_blocking` がブロッキング用のスレッドプールへ渡す。

### エラーは文字列で返す

コマンドの戻りは `Result<T, String>` で統一している。Tauri の IPC が JSON を
渡す以上、型の付いたエラーを送っても向こう側では文字列になる。中身を構造化
したいときは成功側の型に載せる。

### 索引の書き手は一つだけ

Tantivy は一つのディレクトリに対して `IndexWriter` を一つしか許さない。
アプリは起動時にライブラリを一つ開き、排他ロックを取る。だから
`cargo test` は `--test-threads=1` で走らせる。

## フロント側の作法

### ルーティングは自前

ルーティングライブラリは使わず、`src/app/router.tsx` が `location.hash` を
読んで画面を切り替える。デスクトップのウィンドウにはブラウザの戻る／進むが
無いので、履歴の位置を自分で数える必要がある（`piepHistoryIndex`）。

これがないと、進むボタンは行き先の有無にかかわらず常に点灯し、同じアドレスへの
2回の訪問が一つのスクロール位置を共有してしまう。

### サーバー状態は TanStack Query

Rust から取ってくるものはすべて Query が持つ。用途ごとに保持時間を変えている
（`src/lib/queryClient.ts`）。検索補完のように短命な鍵が大量にできるものは
早く捨て、ファセットのように変更が明示的なものは長く持つ。
