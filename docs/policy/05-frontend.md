# 画面の方針

## 画面の構成

| 画面 | 役割 |
|---|---|
| ホーム | 保存件数、使用容量、保存の推移、索引の状態。URL を貼ると保存候補へ進める |
| ライブラリ | 作品・作者・シリーズ・コレクションの4つの見方。棚、絞り込み、並べ替え、保存した検索、一括操作 |
| 作品 | 概要・本文・アセット・履歴・JSON。読む／編集する／EPUB キューへ入れる／書き出す |
| リーダー | 書体・文字サイズ・行間・背景色。読みかけの位置を覚える |
| エディタ | 見出しや段落をブロックとして並べ替え・書き換え。右側で仕上がりを確認 |
| 保存 | 内蔵ブラウザで開いたページから候補を取り、選んだものを保存する |
| 更新センター | 「確認のみ」と「自動保存」。一時停止・再開・中止・失敗分の再試行 |
| EPUB Studio | キューに入れた作品を、テンプレートと画像最適化の設定で書き出す |
| 診断 | 容量、索引の完成度、実データでの検索速度、孤立したアセット |

## 状態をどこに置くか

**画面の見え方を決めるものは、すべて URL に置く。**

これは好みの問題ではない。過去に実際に壊れた箇所である。ライブラリの詳細な
絞り込みだけが React の `useState` にあり、URL には検索語・タブ・お気に入り・
監視・並び順しか載っていなかった。

作品を開くとライブラリはアンマウントされ、state は消える。戻ると初期値で再構築
される。一方で作者ページは同じ絞り込みを URL に持っていた。結果として、
**同じ操作が画面によって違う結果になった**。

| 条件 | パラメータ |
|---|---|
| 検索語 | `q` |
| タブ・棚 | `tab` |
| ソース | `source`（複数可） |
| コンテンツ種別 | `type` |
| 含めるタグ | `tag`（複数可） |
| 除外するタグ | `nottag`（複数可） |
| 複数タグの条件 | `tagmode=or`（`and` は省略） |
| 文字数 | `minchars` / `maxchars` |
| お気に入り・更新監視 | `favorite=1` / `watch=` |
| 改稿あり | `revised=1` |
| 並べ替え | `sort` |

副次的な効果として、**絞り込んだライブラリがそのままリンクできる**ようになり、
保存した検索の復元も URL 一本に統一された。

置き場所の判断はこうなる。

| 種類 | 置き場所 |
|---|---|
| 画面の見え方（絞り込み、並び、タブ、ページ） | **URL** |
| Rust から取ってくるもの | TanStack Query |
| 一時的な UI（開いているモーダル、入力中の文字） | ローカルの `useState` |
| 画面をまたぐ作業状態（EPUB キューなど） | `WorkspaceContext` |

## スクロールと履歴

デスクトップのウィンドウにはブラウザの戻る／進むが無い。だから履歴の位置を
自分で数える（`piepHistoryIndex`）。

**スクロール位置は「アドレス」ではなく「履歴の項目」にぶら下げる。**
同じ一覧を2回訪れたのは、利用者が2回そこに立ったということであり、
クエリ文字列を書き換えただけなら立っている場所は1つのままである。

移動の種類で挙動を変える。

| 移動 | 位置 |
|---|---|
| 新しい行き先へ進む（push） | 先頭から |
| 戻る（pop） | 元いた位置へ復元 |
| クエリ文字列だけの書き換え（replace） | **動かさない**。タブ・絞り込み・並べ替えがこれ |

### ページ送りで一覧が縮まないようにする

ページ番号が変わると Query の鍵が変わり、`isLoading` が立って一覧全体が
ローディング表示に差し替わっていた。6,000px あったページが 900px に縮み、
ブラウザが `scrollTop` をその高さへ切り詰め、読んでいた場所が失われていた。

- `placeholderData: keepPreviousData` で、取得中も前ページを表示し続ける。
  高さが縮まないので位置も失われず、スピナーの明滅も消える
- `useRevealOnChange`（`src/lib/scroll.ts`）で、ページ番号が変わったら
  **一覧の先頭**をヘッダー直下へ持ってくる。プロフィールの先頭ではなく
  「2ページ目の最初の作品」に着地させる

## 大きなライブラリに耐える

- 一覧は仮想化する（`VirtualizedWorkList` / `VirtualizedEntityGrid`）
- キャッシュの保持時間は用途ごとに変える（`src/lib/queryClient.ts`）。
  検索補完のように短命な鍵が大量にできるものは早く捨て、ファセットのように
  変更が明示的なものは長く持つ
- 作者・シリーズの一覧は、ファセットの上位60件ではなく専用の頁送りで引く。
  上位だけでは大きなライブラリのほとんどが見えない

## 時間の語彙

**すべての日付は、取得元の時間か手元の時間のどちらかに属する。混ぜない。**

作者ページの見出しには長らく「更新 2026年8月20日」と出ていたが、これが指して
いたのは取得元での更新ではなく **piep のデータベースの行が書き換わった日**
だった。読む側に区別はつかない。プロフィールを取り直しただけでも動く日付を、
作者が何かをした日として見せていた。

| 軸 | 使う言葉 |
|---|---|
| 取得元の時間 | **公開日**（最初に出した日）・**最終更新**（最後に直した日） |
| 手元の時間 | **保存日**（この版を取った日）・**確認日**（最後に照合した日） |

「更新」は取得元にしか使わない。手元のことは「保存」と「確認」で言う。

### 日付より、ずれを見せる

利用者が知りたいのは日付そのものではなく、**手元の版が取得元に追いついて
いるか**である。それは日付ではなく状態なので、状態として扱う
（`lib/workFreshness.ts` の一箇所で決める。画面ごとに条件を書くと、同じ作品が
画面によって違う顔になる）。

- **改稿あり** — 取得元のほうが新しい。目に入る
- **未照合** — 取得元の最終更新をまだ知らない。控えめに。「最新」と偽らない
- **それ以外** — **何も出さない**

ライブラリのほとんどは常に最新である。全部に「最新」と書けば、その文字は情報を
運ばなくなる。→ [色](#色)の「静かな状態」と同じ考え方で、**既定の状態には
印を付けない。**

印の出どころは `WorkCard` の中に置く。カードが出るところすべてで同じ顔にする
ためで、同じキーの問い合わせは共有されるので何枚並んでも通信は1回である。

### 棚が答えるのは「どれを取り直すべきか」

かつて4つ目の棚は「更新監視」で、`watch_updates` が立った作品を集めていた。
しかし**監視の単位は作者・シリーズであって作品ではない**ので、実際には誰も
作品を立てず、常に空の棚がひとつ置かれていた。

いまは「改稿あり」で、取り込んでいない改稿がある作品を集める。中身は
「読みかけ」と同じ**会員名簿方式**（`idsInclude`）で、絞り込みの SQL を
足していない。空の名簿は「該当なし」であって「絞り込みなし」ではない。

`watch=watched` は絞り込みとしては残る。棚を降りただけである。

### 語ることがない行を作らない

一度も直されていない作品では、最終更新は公開日と同じ瞬間を指す。同じものを
二度書いても情報は増えないので、**その行はそもそも出さない**。確認したことが
無い相手に「—」と書くくらいなら、要素ごと省く。

確認日は近いうちは相対で書く（「2日前に確認」）。ただし遠くなると相対は読み
にくくなるので、30日を越えたら絶対日付へ戻す（`formatFreshness`）。

## 色

**色は状態を示すために使い、要素の種類を示すためには使わない。**

何も設定していない作品のカードに橙・緑・オリーブの文字色が並び、20行の一覧で
約100個の色付きチップが出ていた時期があった。「静かな状態」が存在しなかった。

| 決めたこと | |
|---|---|
| 青 | `#0096FA` — アプリアイコン左ページの青。Mantine 既定の `blue` は使わない |
| 緑 | `#86B918` — アイコン右ページの緑（`leaf[5]` と同じ） |
| 好み | ハートは赤。チップの背景ではなく**アイコンの中身**が塗られる |
| 提供元マーク | pixiv 青・FANBOX 黄は**ブランド色として例外**。アプリの配色規則の外に置く |

pixiv マークもアプリの青と同じ `#0096FA` である。pixiv 作品が大半のライブラリでは
マークがアクセントのように見えるが、提供元マークを現状維持と決めたうえで
受け入れている。

## 表紙のない作品

表紙が無い作品にも、棚に並べたときに見分けが付く絵を作る。

```
┌──────────────┐
│▔▔▔▔▔▔▔▔▔▔▔▔▔▔│ 提供元の細帯
│ ■ ■          │ 印 = 作品IDから決まる 5×5 の左右対称パターン
│  ■■■         │
│              │
│  シリーズ名   │ ← あるときだけ
│  タイトル     │ ← 主役。文字数で3段階
└──────────────┘   地色 = 作者名から決まる12段の色相
```

- **印は作品ごと、色は作者ごと。** 同じ棚に同じ絵が並ばず、同じ作者の作品は
  色でまとまる
- **46px（リスト表示）では印だけ。** 読めない大きさに文字を置かない
- **作者名はタイルに書かない。** カード本体がすぐ隣に出している
- 色相は12段に量子化する。`hash % 360` は日本語の作者名が近い値に固まり、
  9人中4人が同じ緑になった。FNV-1a で混ぜてから落としている
  （`src/lib/coverSigil.ts`）
