# 画面の方針

## 画面の構成

| 画面 | 役割 |
|---|---|
| ホーム | 保存件数、使用容量、保存の推移、索引の状態。URL を貼ると保存候補へ進める |
| ライブラリ | 作品・作者・シリーズ・コレクションの4つの見方。棚、絞り込み、並べ替え、保存した検索、一括操作（選んだ作品をそのままコレクションにまとめられる） |
| 作品 | 概要・本文・アセット・履歴・JSON。読む／編集する／EPUB キューへ入れる／書き出す |
| リーダー | 書体・文字サイズ・行間・背景色。読みかけの位置を覚える |
| エディタ | 見出しや段落をブロックとして並べ替え・書き換え。右側で仕上がりを確認 |
| 保存 | 内蔵ブラウザで開いたページから候補を取り、選んだものを保存する |
| 新作・改稿 | 「新作だけ」と「改稿も」、「確認のみ」と「自動保存」。一時停止中の候補選択と一括保存、再開・中止・失敗分の再試行 |
| EPUB Studio | キューに入れた作品を、テンプレートと画像最適化の設定で書き出す |
| 診断 | 容量、索引の完成度、実データでの検索速度、DB未登録の画像・添付 |

### 一覧と型を二重に書かない

設定の区画は URL に載る。型（`Section`）と実体の一覧（`SECTIONS`）を別々に
書いていたので、脇の項目を足したときに一覧を直し忘れ、**押しても何も起きない
項目**ができた。一覧に無い値は弾かれて既定へ戻るので、押した本人には理由が
見えない。一覧から型を導いて、ずれようがなくする。

```ts
const SECTIONS = ["connections", ...] as const;
type Section = (typeof SECTIONS)[number];
```

同じ形のものは他にもある（タブ、並べ替えの鍵）。見つけたら同じ形に直す。

### 日本語は文節で折る

`body` に `word-break: auto-phrase` を敷いている。既定の `normal` は CJK を
どの文字の間でも折るので、「入れられま／す。」「キモデブ／が溺愛されて」のように
**読みの単位を割って改行**していた。

例外は折る場所を持たない文字列 — 保存先のパス、URL、識別子。`code` 系と
`.break-anywhere` だけ `overflow-wrap: anywhere` に戻す。

### 通知で操作列を覆わない

通知は固定ヘッドバーと、編集・読書画面の操作列より下に置く。保存通知が
「反映」や読書設定を覆うと、押せないだけでなく、ポインターが通知の上に
とどまって自動消去も止まる。通知が残ったまま画面を移った場合も、移動先の
操作列を避ける。

### プレビューにも中身を置く

ブラウザプレビューはデモデータで動く。コレクションだけ空にしておくと、
**カードの崩れがデスクトップ版でしか見つからない**。表紙のあるもの・無いもの・
名前の長いものを一通り `demoCollections` に並べてある。

`getAssetUrl` はブラウザプレビューでだけ `data:` と `http(s):` をそのまま通す。
デスクトップ版は管理されたローカルパスだけを `convertFileSrc` へ渡す。実DBに
URLが紛れ込んでも、棚を開いただけで外部画像へ通信してはいけない。

### 同じものは同じ顔で出す

コレクションの中身は、棚とまったく同じ `WorkCard` で描く。束にしかない情報
（何番目か、順を入れ替える、外す、別版を畳む）だけをカードの外側のレールに置く。

これができていなかったのは好みの問題ではなく、**型が合わなかったから**である。
`get_work_collection` が縮小した投影を返していたので `WorkCard` に渡せず、
表紙と題名と字数だけの行を手で組み直していた。保存側が `DownloadEntry` を返す
ようにした時点で、棚の作り込み（タグ行・作者の顔・お気に入り・EPUBキュー・
改稿の印・複数選択）はそのまま束の中でも効く。

一覧の中で一種類だけ見え方が違うと、それは作りかけに見える。

### スクロールバー

スクロールバーの出入りで中身の幅を動かさない。幅と色は `app.css` の冒頭で全体に一つ決め、
地を透かす。スクロールする領域は必ず `scrollbar-gutter: stable` で場所を取り、取った分を
余白から引いて左右を揃える。横のバーは `overflow-x: scroll` で場所を取る。バーを出さない
領域だけ `scrollbar-width: none` にする。画面のコードに `overflow: auto` を直接書かず、
`piep-scroll-y` を使う。`src/styles/scrollbars.test.ts` と視覚試験が見張る。

### 操作の列

毎回触る操作は一列に収める。折り返すと、右端の開始ボタンの居場所が幅で変わる。狭いときは
補足の言葉から畳み、説明は ? で開く。選んだときだけ必要な注意は列の下に出す。

### β版の印

β版の機能には `BetaBadge` を付ける。設定では一覧の項目と `SectionIntro` の見出しに印を付ける。項目ごとに形を変えない。何が変わり得るかは利用の手引きに書く。毎回目に入る大きな注意は、使う前に知らないと困ることがあるときだけ黄色の `Alert` で出す。

### 情報は左、操作は右

押しボタンの置き場所を画面ごとに考えない。探す先がいつも同じなら、読まずに押せる。

- **操作は、それが属する枠の右端に揃える。** ページの見出し、カードの見出し、カードやフォームの足元、ダイアログの足元、一覧の行が該当する。足元には `ActionRow` を使う。
- **主操作は列の右端に置く。** 読み進めた終点に決定がある。左へ行くほど軽い操作にする。「その他」のメニューだけは主操作のさらに右に置く。
- **解除・削除・中止は白地・赤枠・赤文字。** `DangerButton` を使い、確認の決定には `DANGER_CONFIRM` を渡す。地を赤く塗らない。赤が要るのは、消す操作と進行中の処理を止める操作である。再試行は赤くしない。赤は状態の色で、やり直す操作の色ではない。確認の「キャンセル」も赤くしない。ふだん使わない解除は、その他のメニューへ入れる。一覧の行に並ぶアイコンだけの削除は、枠を付けず赤いアイコンにする。
- **押せるものは押せる形にする。** 文字だけのボタンを作らない。`variant="subtle"` の `Button` には地と細い枠が常に付く（`app.css`）。色を指定しなければ灰色で、青は使わない（`theme.ts`）。青の濃い文字と薄い地の組み合わせは主操作より目立ち、重さが逆になる。赤など意味のある色だけ `color` で渡す。文の中のリンクのように読ませたいものだけ `.button-plain` で外す。
- **文字を書くのは主操作だけ。** 詳細見出しの補助操作は、枠の付いたアイコンとツールチップにする（`ActionBar`）。全部に文字を書くと、同じ重さの札が並んで主操作が埋もれる。主操作はその列でいちばん横長にする。
- **作品の操作は読むが先頭。** 上の「主操作は列の右端」の例外で、カードと詳細画面のどちらも読むを左端に置く。詳細画面は 読む・編集 と、手元の印と置き場（お気に入り、EPUB、コレクション）に分けて寄せる。その他だけは右端。
- **詳細見出しの印と補助操作は同じ段に置く。** 操作だけの段を立てると左が空き、題が下へ押される。印は左から流して段の中で折り返し、操作は右上から動かさない。題やシリーズ名は次の段から全幅で折り返す。
- **左に置くのは、見え方を変えるものと選ぶ道具。** 検索、絞り込み、範囲、タブ、「表示分を選択」「選択を解除」は決定ではない。選んだものへの決定は同じ行の右に置く（`ActionRow` の `start`）。
- **折り返しても右に残す。** `justify="space-between"` の行は折り返すと右の塊が左端へ落ちるので、右の塊に `ml="auto"` を付ける。`ActionRow` はこれを済ませてある。
- **全幅の決定は、幅の狭い柱の中だけ。** EPUB の出力、保存候補、作者の監視のような柱では全幅にする。カードの半分を超える幅で全幅にしない。
- **スイッチは2通り。** カード全体を切り替えるなら見出しの右端、フォームに並ぶ項目なら項目名の左。項目名から1,000px 離れたスイッチは、どの行のものか目で追えない。

例外は、右へ寄せると文脈から離れるものである。本文の直後の「続きを読む」、入力欄のすぐ右の「追加」、空の状態の案内やページ送りは、それぞれ文のそば、欄の隣、中央に置く。

### 切り替わりは前後をつなぐ

タブや表示形式を押すと、いま見ている一覧がまるごと別のものへ変わる。何の繋がり
も無く入れ替わると、目は毎回いちから配置を読み直すことになる。**変わったものだけ
を差し替え、変わらないものは1ピクセルも動かさない。**

- 入れ替わる領域は `transitionContent`（`src/lib/contentTransition.ts`）に通す。
  View Transitions で、**領域そのものは動かさず**中身だけを差し替える。文字は
  先に消してから（80ms）現れる（70ms 遅れて 160ms）ので、二重に重なって読めない
  時間が無い
- **中のカードは対応づけない。** 一度そうしてみたが、二重に誤っていた。タブを
  またぐと1枚目どうしは別の作品で、結び付ける意味が無い。しかも前後で同じ格子を
  使うので枠は数ピクセルしか動かず、その動きは文字が現れ終わった**あと**に届く。
  出来上がった画面が自分で位置を直しているように見える
- 選択中のタブを示す下線は Mantine の `border-bottom` ではなく独立した要素にし、
  押した先へ滑らせる（`MotionTabs`）。役割・キーボード操作・見た目は Mantine の
  まま。**尾を引く緩急は使わない** ―― 距離の大半を先に詰めて最後の数ピクセルを
  這うと、それも「画面が自分を直している」ように見える
- **タブごとに意味を持たない道具は、消さずに隠す。** 消すと残りが横へ寄り、
  同じ押しボタンをタブを移るたび目で探し直すことになる。`display: contents` の
  包みに入れ、`visibility` と `inert` で触れなくする
- 動きは、画面を更新している窓でしか進まない。最小化や遮蔽で更新が止まると遷移
  は始まらないまま固まるので、**0.6 秒で見切りをつけて**動きを捨て、内容だけを
  差し替える
- 「視覚効果を減らす」設定（`prefers-reduced-motion`）では、どの動きも出ない。
  差し替えだけが即座に起きる

## 状態をどこに置くか

**画面の見え方を決めるものは、すべて URL に置く。**

これは好みの問題ではない。過去に実際に壊れた箇所である。ライブラリの詳細な
絞り込みだけが React の `useState` にあり、URL には検索語・タブ・お気に入り・
監視・並び順しか載っていなかった。

作品を開くとライブラリはアンマウントされ、state は消える。戻ると初期値で再構築
される。一方で作者ページは同じ絞り込みを URL に持っていた。結果として、
**同じ操作が画面によって違う結果になった**。

| 条件 | パラメータ |
|---|---|
| 検索語 | `q` |
| タブ・棚 | `tab` |
| ソース | `source`（複数可） |
| コンテンツ種別 | `type` |
| 含める・除外する作者 | `author` / `notauthor`（複数可） |
| 含めるタグ | `tag`（複数可） |
| 除外するタグ | `nottag`（複数可） |
| 複数タグの条件 | `tagmode=or`（`and` は省略） |
| 文字数 | `minchars` / `maxchars` |
| お気に入り・更新監視 | `favorite=1` / `watch=` |
| 改稿あり | `revised=1` |
| 検索する版 | `versions=all`（現在版だけの場合は省略） |
| 添付数・容量 | `minassets` / `maxassets`、`minsizemb` / `maxsizemb` |
| 添付種別・シリーズ所属 | `assets` / `seriesmode` |
| 改稿・ローカル編集・表紙 | `revision` / `localedit` / `cover` |
| 日付の種類と範囲 | `datefield` / `datefrom` / `dateto` |
| 作品の並べ替え | `sort` / `order` |
| 作者・シリーズの並べ替え | `esort` / `eorder` |
| コレクションの並べ替え | `csort` / `corder` |
| 作者・シリーズ一覧の条件 | `emin` / `edone` / `ewatch` |
| 読書中・改稿待ちの棚 | `shelf=reading` / `revised=1` |

副次的な効果として、**絞り込んだライブラリがそのままリンクできる**ようになり、
保存した検索の復元も URL 一本に統一された。

置き場所の判断はこうなる。

| 種類 | 置き場所 |
|---|---|
| 画面の見え方（絞り込み、並び、タブ、ページ） | **URL** |
| Rust から取ってくるもの | TanStack Query |
| 一時的な UI（開いているモーダル、入力中の文字） | ローカルの `useState` |
| 画面をまたぐ作業状態（EPUB キューなど） | `WorkspaceContext` |

## スクロールと履歴

デスクトップのウィンドウにはブラウザの戻る／進むが無い。だから履歴の位置を
自分で数える（`piepHistoryIndex`）。

**スクロール位置は「アドレス」ではなく「履歴の項目」にぶら下げる。**
同じ一覧を2回訪れたのは、利用者が2回そこに立ったということであり、
クエリ文字列を書き換えただけなら立っている場所は1つのままである。

移動の種類で挙動を変える。

| 移動 | 位置 |
|---|---|
| 新しい行き先へ進む（push） | 先頭から |
| 戻る（pop） | 元いた位置へ復元 |
| クエリ文字列だけの書き換え（replace） | タブは動かさない。一覧を総入れ替えする検索・絞り込み・並べ替えは、結果が届いてから一覧先頭へ移す |
| 同じ棚をもう一度選ぶ（明示 `scroll: top`） | 履歴を増やさず先頭へ戻す |

遅れて届く結果に付随する移動は、要求した `navigationId` と一覧のURLへ結び付ける。
その間に戻る／進む、別の条件への移動、手動スクロールが起きたら予約を捨てる。
古い問い合わせの完了が、別の履歴項目へ復元した位置を上書きしてはならない。

### ページ送りで一覧が縮まないようにする

ページ番号が変わると Query の鍵が変わり、`isLoading` が立って一覧全体が
ローディング表示に差し替わっていた。6,000px あったページが 900px に縮み、
ブラウザが `scrollTop` をその高さへ切り詰め、読んでいた場所が失われていた。

- `placeholderData: keepPreviousData` で、取得中も前ページを表示し続ける。
  高さが縮まないので位置も失われず、スピナーの明滅も消える
- ページ番号が変わったら、新しい行が確定したフレームで**一覧の先頭**を
  ヘッダー直下へ持ってくる。プロフィールの先頭ではなく「2ページ目の最初の作品」
  に着地させる。移動予約は履歴移動や利用者のスクロール意図で取り消す

## 大きなライブラリに耐える

- 一覧は仮想化する（`VirtualizedWorkList` / `VirtualizedEntityGrid`）
- キャッシュの保持時間は用途ごとに変える（`src/lib/queryClient.ts`）。
  検索補完のように短命な鍵が大量にできるものは早く捨て、ファセットのように
  変更が明示的なものは長く持つ
- 作者・シリーズの一覧は、ファセットの上位60件ではなく専用の頁送りで引く。
  上位だけでは大きなライブラリのほとんどが見えない

## 時間の語彙

**すべての日付は、取得元の時間か手元の時間のどちらかに属する。混ぜない。**

作者ページの見出しには長らく「更新 2026年8月20日」と出ていたが、これが指して
いたのは取得元での更新ではなく **piep のデータベースの行が書き換わった日**
だった。読む側に区別はつかない。プロフィールを取り直しただけでも動く日付を、
作者が何かをした日として見せていた。

| 軸 | 使う言葉 |
|---|---|
| 取得元の時間 | **公開日**（最初に出した日）・**最終更新**（最後に直した日） |
| 手元の時間 | **保存日**（この版を取った日）・**確認日**（最後に照合した日） |

「更新」は取得元にしか使わない。手元のことは「保存」と「確認」で言う。

### 日付より、ずれを見せる

利用者が知りたいのは日付そのものではなく、**手元の版が取得元に追いついて
いるか**である。それは日付ではなく状態なので、状態として扱う
（`lib/workFreshness.ts` の一箇所で決める。画面ごとに条件を書くと、同じ作品が
画面によって違う顔になる）。

- **改稿あり** — 取得元のほうが新しい。目に入る
- **未照合** — 取得元の最終更新をまだ知らない。控えめに。「最新」と偽らない
- **それ以外** — **何も出さない**

ライブラリのほとんどは常に最新である。全部に「最新」と書けば、その文字は情報を
運ばなくなる。→ [色](#色)の「静かな状態」と同じ考え方で、**既定の状態には
印を付けない。**

印の出どころは `WorkCard` の中に置く。カードが出るところすべてで同じ顔にする
ためで、同じキーの問い合わせは共有されるので何枚並んでも通信は1回である。

### 棚が答えるのは「どれを取り直すべきか」

かつて4つ目の棚は「更新監視」で、`watch_updates` が立った作品を集めていた。
しかし**監視の単位は作者・シリーズであって作品ではない**ので、実際には誰も
作品を立てず、常に空の棚がひとつ置かれていた。

いまは「改稿あり」で、取り込んでいない改稿がある作品を集める。中身は
「読みかけ」と同じ**会員名簿方式**（`idsInclude`）で、絞り込みの SQL を
足していない。空の名簿は「該当なし」であって「絞り込みなし」ではない。

`watch=watched` は絞り込みとしては残る。棚を降りただけである。

### 語ることがない行を作らない

一度も直されていない作品では、最終更新は公開日と同じ瞬間を指す。同じものを
二度書いても情報は増えないので、**その行はそもそも出さない**。確認したことが
無い相手に「—」と書くくらいなら、要素ごと省く。

確認日は近いうちは相対で書く（「2日前に確認」）。ただし遠くなると相対は読み
にくくなるので、30日を越えたら絶対日付へ戻す（`formatFreshness`）。

## 色

**色は状態を示すために使い、要素の種類を示すためには使わない。**

何も設定していない作品のカードに橙・緑・オリーブの文字色が並び、20行の一覧で
約100個の色付きチップが出ていた時期があった。「静かな状態」が存在しなかった。

| 決めたこと | |
|---|---|
| 青 | `#0096FA` — アプリアイコン左ページの青。Mantine 既定の `blue` は使わない |
| 緑 | `#86B918` — アイコン右ページの緑（`leaf[5]` と同じ） |
| 好み | ハートは赤。チップの背景ではなく**アイコンの中身**が塗られる |
| 提供元マーク | pixiv 青・FANBOX 黄は**ブランド色として例外**。アプリの配色規則の外に置く |

pixiv マークもアプリの青と同じ `#0096FA` である。pixiv 作品が大半のライブラリでは
マークがアクセントのように見えるが、提供元マークを現状維持と決めたうえで
受け入れている。

## 表紙のない作品

表紙が無い作品にも、棚に並べたときに見分けが付く絵を作る。

```
┌──────────────┐
│▔▔▔▔▔▔▔▔▔▔▔▔▔▔│ 提供元の細帯
│ ■ ■          │ 印 = 作品IDから決まる 5×5 の左右対称パターン
│  ■■■         │
│              │
│  シリーズ名   │ ← あるときだけ
│  タイトル     │ ← 主役。文字数で3段階
└──────────────┘   地色 = 作者名から決まる12段の色相
```

- **印は作品ごと、色は作者ごと。** 同じ棚に同じ絵が並ばず、同じ作者の作品は
  色でまとまる
- **46px（リスト表示）では印だけ。** 読めない大きさに文字を置かない
- **作者名はタイルに書かない。** カード本体がすぐ隣に出している
- 色相は12段に量子化する。`hash % 360` は日本語の作者名が近い値に固まり、
  9人中4人が同じ緑になった。FNV-1a で混ぜてから落としている
  （`src/lib/coverSigil.ts`）

## テーマ

ライトとダークの両方に対応する。スクリーンショットも両方で撮る。


### ライブラリの表示と状態確認

サイドバーの「すべて」は常に表示する。お気に入り・読みかけ・改稿あり・要確認は外観設定で
個別に非表示にできる。設定は端末内に保持し、作品や検索条件は変更しない。非表示のときも
ライブラリの表示対象メニューから同じ一覧へ移動できる。

作品詳細は取得状態の理由と記録時点を表示する。欠落画像は本文のページ・前後の文章から
位置を確認できる。ローカル編集がある場合も、取得時の保存版へ明示して位置を合わせる。

診断の主要操作は保存状態の確認と、検出された問題の修復とする。容量・検索速度などの
技術的な数値と、DBや索引の保守は開閉して確認する。未登録ファイルを破損や削除可能な容量と
同一視しない。修復中の対象、完了件数、残件を分け、画面を戻っても実行状態を復元する。
