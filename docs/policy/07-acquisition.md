# 取得の方針

piep が外部と通信するのは、**pixiv と FANBOX からデータを取得するときだけ**である。
それ以外の通信路は持たない。

## 相手のサービスに負担をかけない

これは礼儀の問題であると同時に、**利用者のアカウントを守るための実務**でもある。
乱暴に取ると制限を受けるのは利用者本人である。

- 画像などのアセット取得は同時 2 本に制限する
  （`asset_downloader.rs` のセマフォ）
- 更新確認は1件ずつ進め、通常は2秒以上あける
- 速く大量に取ることを目的にした機能は作らない。
  制限を迂回する仕組みも作らない

利用にあたっては pixiv および FANBOX の利用規約に従う。

## 認証

内蔵の WebView2 でサービスにログインする。**piep がパスワードを受け取ることは
ない。** 利用者はサービス自身のログイン画面に入力する。

| サービス | 方式 |
|---|---|
| pixiv | OAuth。未認証／アクセストークンのみ／自動更新付きリフレッシュトークンの3状態を扱う（`pixiv_api/token_manager.rs`）。加えて、ログイン画面を通ったときに web のセッション Cookie も受け取る |
| FANBOX | セッション Cookie |

pixiv の Cookie は**付け足しであって、接続の条件ではない**。取れなくてもログインは
成功とし、更新確認は従来の経路で動く。Cookie は UA と対でだけ意味を持つので
（`cf_clearance` が発行時の UA に紐づく）、**片方だけを保存しない**。

取得用接続と内蔵ブラウザの表示用ログインは、別の WebView2 プロファイルで保持する。
表示用ブラウザでログイン・ログアウトしても、保存と更新確認に使う資格情報は変えない。

### 要る鍵だけを持つ

ログイン窓が持ち帰る Cookie には、解析や広告の識別子まで混じっている
（実測で pixiv は 36 個 2,869 文字、FANBOX は 14 個 1,086 文字）。
**相手が要るのはセッションひとつで、実測でもそれだけで返事は変わらない。**

残すのは次の二つだけとし、取得元ごとに別の作法を作らない
（`auth::essential_cookies`）。

- セッション（`PHPSESSID` / `FANBOXSESSID`）— 名乗るための鍵そのもの
- `cf_clearance` — 内蔵ブラウザが自分で通り抜けた Cloudflare の通行証

**利用者の閲覧履歴に当たるものを、送りもしないし持ちもしない。**
保存済みの古い値にも同じ規則を通すので、繋ぎ直さなくても余計なものは出ていかない。

## 二つの口を、仕事で分ける

pixiv のアプリ API と web API は取得できる情報が異なる。
用途に合う経路を使い、取得できなかった項目だけをもう一方で補完する。

| 仕事 | 使う口 | 理由 |
|---|---|---|
| 本文・挿絵の取得 | アプリ API（`/webview/v2/novel`） | 本文と挿絵参照を取得する |
| 挿絵の再確認 | web（`/ajax/illust/{id}/pages`） | 取得用の接続で、アプリ API が隠した画像や代替画像を再確認する |
| 変わったかどうかの検出 | web（`/ajax/user/{id}/profile/novels`） | 更新時刻を持ち、100件をまとめて返す |
| 一覧で省かれた作品の確認 | web（`/ajax/novel/{id}`） | 個別詳細の `uploadDate` は一覧の `updateDate` と同じ時刻を示す |
| シリーズの表紙 | web（`/ajax/novel/series/{id}`） | アプリ API は各話の画像しか返さない |
| 本文の退避路 | web（`/ajax/novel/{id}`） | 本文の中身はアプリ API と一致する。切り出しが壊れた日のために |

本文の退避路は、切り出しの失敗に加え、作品詳細は存在するのに本文用APIだけが404を
返す場合にも使う。取得制限では待機する。web が解決しない `[pixivimage:]` は画像詳細で
補う。アプリ API の404・閲覧不可・代替画像だけで取得不能とは決めず、取得用アカウントの
web 接続でも確認する。Cookie と User-Agent はジョブに閉じ、表示用ブラウザーの接続を混ぜない。
両経路で閲覧できない画像があっても本文と作品情報を保存し、参照を「一部保存」として残す。
説明やタグが空で返された場合は web の作品詳細から補完し、その応答は本文の退避路でも再利用する。

一覧は、接続済みでもPixiv側のR-18表示設定によって作品を省くことがある。
不足・伏せ字・更新日時なしの項目だけを個別詳細で確認し、確認できない応答を
「変更なし」に置き換えない。多数の個別確認が必要な間も一時停止・中止を受け付ける。
個別詳細まで404が続く場合は、大量の作品を利用不能と決める前に停止する。
更新日時はタイムゾーンの表記を含む文字列ではなく、同じ瞬間かどうかで比較する。

取得した資格情報はローカルにのみ保存する。**ログや診断の出力に混ぜない。**

## 保存の流れ

```
内蔵ブラウザでページを開く
   ↓ 「候補を取得」
そのページから見つかった作品・シリーズ・作者を候補として並べる
   ↓ 利用者が選ぶ
本文 JSON と画像を downloads/ へ保存し、メタデータを piep.db へ
```

**候補の提示と実際の保存を分ける。** 開いたページから何が取れるかを見せてから、
何を取るかを利用者が決める。

## 保存するもの

- 本文（原本の JSON をそのまま `original_json_path` に）
- 画像などのアセット
- タグ、公開日、作者、シリーズといったメタデータ

→ [データの持ち方](04-data.md)

## 取得できなかったとき

失敗の理由には分類の札を付ける（`[取得制限]` など）。ジョブは失敗した分だけを
後から再試行できる。**全部やり直させない。**

通信・一時的なサーバーエラー・取得制限は、項目を未処理のまま再試行し、続く場合は
ジョブを一時停止する。作品固有の閲覧条件待ちや画像の一部保存と混ぜて保留にしない。
一覧の完全性を確認できない場合も未処理で停止し、後続の作者を確認済みにしない。

閲覧制限は通信障害と区別し、`held`（保留）として保存する。通常の更新確認・
失敗分の再試行・まとめ保存では再取得しない。一覧の `isRestricted` が分かっている
ときは本文への問い合わせ自体を省く。空の本文・添付や閲覧制限のプレビューを
保存成功にせず、保存先フォルダーも作らない。保存済みの完全な版は守る。

保存済みの作品が公開元で見つからない場合は、手元の版を保持し、利用不能の状態と理由を
通常ライブラリの要確認フィルタにも残す。閲覧条件待ちとは区別し、次の確認では再度
公開元を確認する。閲覧可能な状態を確認したら利用不能の札を外すが、過去のジョブ結果は
その時点の記録として残す。解決済みの状態を再起動時の移行で戻さない。

「保留・非表示」は期限なく残る、取り消せる一覧とする。支援プラン・連携アカウント
の変更後、利用者が選んだ作品だけを再確認する。必要額と作者IDが分かる場合は
支援プランをジョブにつき一度だけ照合し、不足している投稿の本文は取得しない。
閲覧可能になったものだけ候補へ戻し、保存・監視登録は利用者の別操作とする。
非表示の一括解除でも閲覧制限は解除しない。保留状態と理由はバックアップに含める。

保存済み作品の「要確認」は通常のライブラリで取得状態を絞り込む。
一部保存・見つからない・閲覧条件待ち・取得エラー・非表示も同じ絞り込みで選べる。
非表示は利用者が見たうえで外した作品なので、要確認とその種類別の絞り込み、サイドバーの
件数には数えない。「要確認なし」「要確認」「非表示」は重ならず、非表示の作品は「非表示」で引ける。
未保存の保留候補は更新画面に残す。保留一覧は40件ずつ描画し、保存済み詳細の有無で
状態表示や操作欄の位置を変えない。

候補・保留・結果の行は、取得元・作品名・状態・操作の順序を揃える。長い理由を
本文のように常時表示せず、共通の状態札から詳細を開く。状態の名称と色は
ライブラリの取得状態と同じ定義を使う。

旧保存分に欠落記録がなくても、画像参照と実ファイルを照合して一部保存を補完する。
一度に32作品までの背景処理とし、保存・更新中は待機する。検査済みの版と検査の規則を記録し、
再起動で全JSONを読み直さない。規則を増やしたときだけ、旧規則で検査した版を一度見直す。
原本・本文・版数と利用者の非表示や未処理の改稿候補は変えない。

アプリ API は R-18 作品の題名・説明・タグを空で返し、表紙を年齢確認の案内画像に
差し替えることがある。案内画像の表紙と空の項目が揃い、web の作品詳細を確かめていない
保存は、作品情報が伏せられた一部保存として扱う。web で確かめても空の項目は作者が
空にしたものとみなし、一部保存にしない。伏せられていた項目を埋めるだけの保存は補完とし、
作者の改稿に数えない。補完の取り直しでも伏せられたままなら、完了にせず一部保存として残す。

既存の一部保存作品と、実際の挿絵の代わりに閲覧制限の案内画像が保存された作品は、
取得用の接続が揃い、ほかの保存処理が終わったあとに自動で再確認する。作品ごとに
一度だけ試し、取得できた情報を通常の保存処理で補完する。古い版や画像は削除しない。
件数が多い場合は1ジョブ50作品までに分け、ジョブの間を1分以上あける。
この保存処理では、保存済みの一部保存候補に限り、一般的な保留候補の取得抑止を適用しない。
利用者の非表示、未保存の候補、閲覧条件待ちを自動で解除しない。

保存履歴には取得元の変更と補完の区別を記録し、検索・棚件数・改稿回数・バックアップで共有する。
本文が同じで、不足していた情報だけを追加した場合は補完とする。既存の題名・説明・タグなどの
変更を補完に混ぜない。補完による保存コピーは履歴に残すが、作者の改稿には数えない。

投稿自体の無料公開・必要額変更など、保留時の情報が古くなる場合もある。
「投稿の公開条件も再確認」では古い必要額による事前判定を省き、選んだ投稿を
1件ずつ確認する。一度に20件まで、開始間隔は1分以上とし、実際の閲覧制限は
必ず尊重する。これにより、支援プランを上げなければ永久に戻せない状態を避ける。

過去の候補を次の更新確認に戻すのは、現在選択されている監視対象に属する場合だけ。
作者名ではなく取得元のIDで照合する。一度きりの保存失敗が作者の監視登録を意味する
ことはない。保存元がなくなった改稿候補は未保存の新作へ正規化する。

結果表示は全件失敗・一部失敗・完了（保留あり）を区別し、保留をエラーや保存済みの
件数に混ぜない。生のジョブ状態 `failed` は互換性のため維持し、成功した処理が
混在する場合に表示層で「一部失敗」とする。

前の回から同じ種類の理由で保留のままの作品も、確認はそのつど行う。ただし
「保留」には数えず、「完了（保留あり）」や通知の理由にもしない。何も変わって
いないのに毎回知らせると、新しく起きたことが埋もれる。件数は「変わらない保留」
として控えめに示し、保留そのものは要確認に残す。新しく保留になったものと、
保留の種類が変わったもの（見つからない→一部保存など）は、これまでどおり知らせる。

利用者が編集で欠けた挿絵を差し替えた作品は、一部保存として扱わない。編集を
下ろせば、欠けはまた要確認に戻る。

## 取得先への配慮

PixivのAPIクライアント・アクセストークンとFANBOXの接続はジョブ内で再利用する。
認証情報の異なるジョブ間では共有しない。APIの間隔は取得元ごとにアプリ全体で
800ms以上あけ、Web API・ページ送り・表紙修復・同時ジョブにも適用する。429では `Retry-After` を
尊重し、指定がなければ60秒待つ。再試行はジョブ側だけが担い、多重化しない。
FANBOXのCloudflare確認は連続再試行せず一時停止する。保留の明示的な再確認も
開始間隔を1分以上あける。閲覧制限を回避する経路は設けない。

既存表紙の修復は保存・更新ジョブの実行中に待機し、利用者の取得操作を優先する。
R-18とR-18Gの両方の代替画像を対象にし、修復で版を増やさない。EPUBもDBで選ばれた
現在の表紙を優先し、フォルダーに残った代替画像を再採用しない。

## 改稿の扱い

同じ作品を取り直したとき、前の版は `download_versions` に残る。
上書きして消すことはしない。

旧保存分で画像だけが補修された場合も、本文の指紋だけで変更なしにしない。

同じ取得元URLの画像は、保存名が変わっても過去の版から検証済みファイルを再利用する。
旧版のJSONは保存処理ごとに一度だけ調べ、画像ごとに全版を読み直さない。
ハードリンクで実体を共有し、対応しない保存先では検証したローカルコピーを試す。
両方を利用できない場合にだけ再取得する。URLが変わった画像や壊れたファイルを使い回さない。
URLの内容を変えるクエリは保持し、Pixiv・FANBOXの画像配布元で既知の認証クエリだけを同一性の比較から除く。

### 作品情報を含む版の比較

保存版と未保存の改稿を同じ項目で比較する。本文だけでなく、題名・説明・タグ・作者・
シリーズ・公開更新日時・表紙・挿絵・添付の追加変更削除を表示する。FANBOXは本文の構成・
リンク・書式も対象とする。古い版に記録のない値は現在の作品情報から捏造せず、比較不能とする。
保存済み画像はバイト列も比較し、保存場所や認証用URLパラメーターだけの差を内容変更としない。
未保存プレビューは未ダウンロードを欠落と判定しない。画像・添付だけの投稿も比較できる。

候補・保留・結果の副情報は作者・公開日・更新日を優先し、日付がなければ保存日を使う。
一覧の副情報を埋めるために各作品のJSONや画像を読み直さない。取得元への操作はアプリ内の
ブラウザーを開き、取得用の接続情報と閲覧用のログイン状態は分けて扱う。

作者・シリーズの明示的な修復は不完全なキャッシュで成功扱いせず、接続先で再確認する。
認証切れや取得制限では一時停止し、それ以外の取得エラーも3件続けば停止する。
削除や閲覧制限は取得元が答えを返しているので、何件続いても連続エラーに数えず、間隔も空けない。
削除や閲覧条件待ちは他の項目の取得失敗と混同せず、未取得の残件として保持する。
