# 設定と詳細設定

## 何を設定にするか

**コードの中の数のほとんどは、設定にしない。** 応答や画像の最大バイト数、画素数、EPUB の
検査の上限、スキーマの版、画面の寸法、読み込みの単位、判定のしきい値は、壊れた入力から
アプリを守る線か、内部の都合である。変えたい人はおらず、変えられると事故の入口になる。

設定にするのは、**利用者が意味を持って変えたくなる値**だけで、変えると何が起きるかを
一行で言えるものに限る。「取得の間隔を延ばすと、断られにくくなる」は言える。
「索引を書き出す間隔」は言えない。

ふだん触る設定は、それを使う画面の近くに置く（更新の確認の時間割は更新の画面、文字の
大きさは読む画面）。それ以外の細かい値は、設定の「詳細設定」に集める。

## 詳細設定

| 群 | 項目 | 既定 | 範囲 | 使う所 |
| --- | --- | --- | --- | --- |
| 取得元との通信 | 取得元へ問い合わせる間隔 | 0.8 秒 | 0.4〜60 秒 | `downloader/pacing.rs`（pixiv・FANBOX それぞれの門） |
| | 更新の確認で、作品や作者の間にあける時間 | 2 秒 | 1〜60 秒 | `commands/update_jobs.rs` |
| | 新作だけの確認で、作者の間にあける時間 | 1.5 秒 | 0.75〜60 秒 | 同上 |
| | 取得制限に当たった作品をやり直す回数 | 3 回 | 0〜5 回 | 同上 |
| | 失敗が続いたら更新の確認を止める回数 | 3 回 | 1〜10 回 | 同上 |
| | 本文まで突き合わせる間隔 | 14 日 | 7〜90 日 | 同上（[Rust側の方針](06-backend.md)の改稿の見分け方） |
| | 取得元の応答を待つ時間 | 30 秒 | 15〜120 秒 | pixiv・FANBOX の API、画像の配信元。pixiv のウェブ版はこの 3 分の 2 |
| | 画像を同時に取る数 | 2 本 | 1〜2 本 | `downloader/asset_downloader.rs` |

| 履歴 | 更新の確認の履歴を残す件数・日数 | 50 件・30 日 | 10〜500 件・7〜365 日 | 起動したときの整理 |
| | 処理の記録を残す件数 | 100 件 | 20〜500 件 | `features/jobs/operationJobs.ts` |
| サーバーへの自動送信 | 棚の変更が落ち着いてから送るまで | 5 分 | 1〜60 分 | `server/desktop.rs` |

| 読む | 読む速さ | 550 字/分 | 200〜2,000 字/分 | 読み終わるまでの目安 |

### 範囲は一か所にだけ書く

項目・既定・範囲・名前は `src-tauri/src/advanced_settings.rs` の表が一つだけ持つ。値は
アプリのフォルダーの `advanced-settings.json` に置き、画面だけが使う値（読む速さ・処理の
記録の件数）も同じ所に置く。画面は命令（`settings_advanced_get`）で表を受け取って入力欄を
作るので、範囲を画面に書き写さない。ブラウザで開くプレビューだけは Rust に届かないので
写しを持ち、試験が Rust の表と突き合わせる。

**範囲の外は丸めずに断る。** 黙って丸めると、入れた値と効いている値が食い違い、押した本人には
理由が見えない。画面は範囲の外の欄に赤い枠を付けて保存を押せなくし、Rust も保存の命令で断る。
手で書き換えたファイルに範囲の外の値があれば、その項目だけ既定で読む。

### 取得元との通信には、アカウントを守る線を引く

**間隔は既定の半分より縮められない。画像を同時に取る数は既定より増やせない。**
間隔を縮めた人が取得元に断られ、続ければアカウントが止められる。乱暴に取ると制限を受けるのは
利用者本人である（[取得の方針](07-acquisition.md)）。延ばす方向は自由にしてよい。

既定値は、この表ができる前にコードへ書いてあった定数そのものである。新作だけの確認の 1.5 秒は、
1 人あたりの通信が一覧の 1 回だけになるので、毎秒の通信量が通常の確認と揃うように決めた値で、
間隔を縮めても通信の総数は減らない。

### 効くのはいつか

保存した値はその場で効く。ただし、走っている更新の確認は、やり直しの回数と止める回数を
始めたときに読むので、次の確認から変わる。応答を待つ時間は、取得元への接続を作るとき
（保存や確認を始めるとき）に読む。履歴の件数と日数は、次に起動したときの整理で効く。
欠けた作品を取りに行く回数は、補完の候補を選ぶときと、FANBOX の作品を保存するときに読む。
今までの記録は書き換えず、新しい上限で比べ直す。

## 詳細設定にしないもの

候補として見たが、出さないと決めたもの。

| 値 | 今の値 | 出さない理由 |
| --- | --- | --- |
| 取得制限のあとに待つ時間（`RATE_LIMIT_BACKOFF_BASE_MS`） | 60 秒から倍々、最大 5 分 | 短くすると、解けないうちにまた叩く。下げる理由が無い |
| 失敗のあとに待つ時間（`ERROR_BACKOFF_BASE_MS`） | 10 秒から倍々、最大 60 秒 | 同上 |
| FANBOX のページ送りの間（`FANBOX_PAGE_DELAY`） | 0.8 秒 | 上の門の間隔と重なっている |
| pixiv の一覧を辿る途中の待ち（`API_RATE_LIMIT_*`） | 0.75 秒・3 回 | 一つの要求の中の話で、利用者から見えない |
| 原寸化の間隔と止める回数（`original_images.rs`） | 0.5 秒・5 回 | 一度きりの手入れで、毎回は触らない |
| 補完で一度に直す件数 | 50 件 | 裏の補完を短いジョブに分ける単位で、利用者の待ち時間に響かない |
| 接続の時間切れ | 10 秒 | 応答を待つ時間と違って、回線の速さで変わらない |
| 一度に AI へ送る作品の数・あらすじの長さ・校正の量 | 12 件・300 字・6,000 字 | 文脈の長さと、それに結び付いた処理の作りで決まっている。あらすじの長さは文の数やまとめ方がこの値に結び付いていて、単純に変えられない |
| 1 回の確認が持つ記録の上限 | 2,000 行 | 棚を太らせないための上限 |
| 保存した検索の上限 | 100 件 | 当たる人がまずいない |
| 単独サーバーの更新の間隔・監査の日数 | 6 時間・90 日 | サーバー側の設定で、デスクトップの値ではない |

## すでに画面にある設定

詳細設定に入れず、使う画面に置いているもの。

| 値 | 置き場 | 画面 |
| --- | --- | --- |
| 更新の確認の時間割（起動時・間隔・新作だけ・保存まで・通知・範囲） | `settings.json` の `update_schedule` | 更新の画面 |
| 一覧を読むページ数と間隔（3〜60 秒） | 読むたびに指定 | 内蔵ブラウザ |
| 一覧の件数・読み込み方・見え方・余白・テーマ・横の欄 | localStorage | 設定 › 表示と操作 |
| 既定の検索方法・意味検索を使うか | localStorage・`search-settings.json` | 設定 › 検索 |
| 文字サイズ・行間・本文幅・書体・地の色・縦書き | localStorage | 読む画面 |
| AI のつなぎ先・モデル・送る項目・機能ごとの指示 | 棚 | 設定 › AI の手伝い |
| サーバーへ自動で送るか | `server/settings.json` | 設定 › サーバー |

## 項目を足すとき

1. `advanced_settings.rs` の表に一行足し、読み口の関数を書く。既定は今の定数の値にする。
2. 使う所の定数を消して、読み口を呼ぶ。
3. プレビューの写し（`services/advancedSettingsApi.ts`）と、画面の説明（`AdvancedSection.tsx`）を足す。
   どちらも、足し忘れれば試験が落ちる。
4. この章の表を直す。
