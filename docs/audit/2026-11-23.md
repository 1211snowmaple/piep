デスクトップ・単独サーバー・携帯を一つの製品として、データの流れごとに監査し、見つけたものを
根本から直す。この文書は計画と台帳を兼ね、作業のたびに書き足す。台帳に無い問題を放置しない。

- 基準のコミット: `origin/main` の `6f69797e`（0.42.1 の後、#95・#105・#108 まで）
- 作業ブランチ: 項目ごとに `claude/<内容>`（PR は台帳の状態の欄）

## 3. 進め方

1. 領域ごとに読み取りだけの監査を並べて走らせ、結果を台帳に載せる
2. 重大なものから、再現試験 → 修正 → 同じ試験が通る、の順で直す
3. データに触る修正は、実棚の写し（台帳は SQLite の backup、実体はハードリンク）で確かめる。
   利用者の棚そのものは書き換えない
4. 重要な変更は実装と別のモデルで独立にレビューする（Claude で書いたものは Codex が見る）
5. 一つの PR は一つの目的。台帳の ID を PR に書く

## 4. 台帳

重大度: 破損（データの損失・食い違い）/ 停止（保存や送信が失敗）/ 安全 / 表示 / 小
状態: 未調査 / 調査中 / 問題発見 / 修正中 / レビュー中 / 検証済み / 完了 / 保留 / 対象外

「出典」は見つけた担当。S1〜S4 は Codex（GPT-6.2 Sol）の4本、C は Claude。二本が別々に同じものを
見つけたときは両方を書く。CONFIRMED（入口から結果までコードで追えた）でないものは「推定」と書く。
