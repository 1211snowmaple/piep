# 2026-11-07 コード監査と修正

対象はデスクトップ・単独サーバーの `c4777f1` と、Android版の `5991b9c`。
最近のサーバー導入・自己更新・同期、バックアップ、更新確認、添付PDF、読書処理を起点に、
認証・ファイル所有権・接続先切替・資源消費を調査した。3つの担当で分担し、バックアップと
サーバー導入・復旧については別担当による相互レビューも行った。見た目の調整は行っていない。

リリース統合では、デスクトップの最新main `f1638bf`（0.38.0）に移植した。
古い作業ツリーの修正がすでに取り込まれている箇所は重複適用せず、最新版の管理画面、
同期の永続復旧記録、既存フォルダーを改変せず拒否する導入時の権限検査を保持した。

## 修正内容

| 対象 | 原因と影響 | 修正 |
| --- | --- | --- |
| バックアップの作品ファイル | 保存領域内かだけを検査し、作品Aの目録から作品Bのファイルを上書きできた | 取得元を正式な値に限定し、作品キーごとに配置先の所有権を検査。Windowsの大小文字・実体の別名、作品内部のリンク、分割ZIPをまたぐ衝突も拒否 |
| 旧形式の編集画像 | `editor-assets/<DB ID>/` が別ライブラリの同じ数値IDと衝突した | 互換形式を受理した上で、復元先を作品の安定キー配下へ移し、本文編集とアセットの参照を同じように変換 |
| 編集画像の保存・検査 | 編集版だけが参照する画像のZIP収録・存在検査が不十分。対応アセット行がない場合は復元時に参照を失った | 参照画像を収録・存在検査し、対応アセット行がない目録は変更前に拒否 |
| 作者・シリーズ・コレクション | 管理領域内のパスでも別の実体の画像や履歴JSONを指定できた | 既存DBと全復元パートの安定キー・最終配置先を照合し、別所有者への上書きを拒否。同所有者の更新は保持 |
| 保留中の更新候補 | 全体の最新2,000件を取った後で対象を絞るため、別作者の候補が多いと古い候補が戻らなかった | キーで500件ずつ走査し、対象に合う候補を取りこぼさない |
| PDF取り込み | 圧縮後サイズだけではページ・展開文字数・構造木の作業量を制限できず、照合には二乗時間の処理もあった | 読み込み256 MiB、5,000ページ、1ページ25万文字、全体800万文字まで。構造木の探索・生成量にも予算を設け、文字オブジェクトとMCIDの検索をハッシュ表へ変更 |
| 保存HTML | URL検査がアンカーにだけ適用され、`area[href]` や委譲クリック用属性に未検査URLが残った | 非アンカーの`href`と保存データ由来の`data-content-href`を除去 |
| HTTP認証 | JSON・バイナリ本文を抽出した後に認証するため、未認証端末にも大きな受信枠を使わせていた | ルートのミドルウェアで本文受信前に認証・権限検査。認証時のSQLite待機もHTTP実行スレッドから分離 |
| PCからサーバーへの転送 | 307/308により登録用secretや同期本文を転送先へ再送できた | 通常通信と証明書確認の両方で自動リダイレクトを禁止 |
| 同期確定の途中失敗 | ファイル公開後の不要ファイル退避・受信記録の書き込み失敗が巻き戻しの外にあり、受信blobを失って再試行できなかった | 不要ファイル退避、DB再オープン、記録確定まで巻き戻し対象とし、成功後に新本棚を公開 |
| 単独サーバーの再導入 | 先に作ったフォルダーや既存ファイルの明示的なアクセス許可が残り、SYSTEMで動く実行物を書き換えられた | 最新mainの、既存フォルダーや祖先の権限を検査し危険な置き場を改変せず拒否する方式を維持。古い版の指示や不要なDLLも引き継がない |
| 自己更新の既存展開先 | 既存exeを実行し、答えた版だけで署名確認を省略していた | 毎回、署名を検証した配布物から配置し直す |
| 自己更新失敗からの復旧 | 旧版への戻し自体が中断すると、残ったpendingから失敗版を再起動できた。更新前になかったDBも残った | 戻し専用の印で再開し、新版起動より先に復旧を完了。DB存在目録を保存し、新規DBは除去。復元は作業用コピーからの置換とする |
| 更新案内の受信 | PC・AndroidのJSON受信にサイズ上限がなかった | 両方で64 KiBまでに制限 |
| Android読書同期 | 同期中の各要求がそれぞれ次の同期を起動していた | 追加要求を集約して直列化。設定OFF後の待機分は送らない |
| Androidお気に入り | 接続変更後に前サーバーのメモリ状態や遅延応答が残った | 接続変更時に消去し、旧接続の応答を破棄 |
| Android画像 | キャッシュ名は接続A、待機後の取得は接続Bを使う競合があった。WebViewの同一URLキャッシュも再利用された | 接続スナップショットと登録世代を固定し、変更後の返却・保存を拒否。WebViewのURLも起動・接続ごとに分離 |
| Android更新APKの照合 | 既存APKを最大512 MiBまとめてメモリに読んでいた | 64 KiBずつ読みながらSHA-256を計算 |
| 原本の読み込み失敗と検索索引 | 一時的に原本を読めなくても空本文で索引済みとなり、再試行されなかった | 読み込み・解析の失敗を返し、直前の索引と未処理の状態を保持 |
| 作品削除後の旧編集画像 | 旧形式の画像フォルダーが削除対象に入らず残っていた | 作品と同じ削除の隔離・復旧記録へ含め、失敗時や中断後も他作品を巻き込まず処理 |

主な実装はデスクトップ側の `src-tauri/src/commands/archive.rs`、`commands/update_jobs.rs`、
`pdf/`、`server/`、`src/lib/content.ts`、Android側の `src-tauri/src/pc_client/cover_protocol.rs`、
`src-tauri/src/app_update.rs`、`src/readingSync.ts`、`src/favorites.ts`、`src/images.tsx` にある。

## 依存関係

RustSecが検出した該当バージョンを次の修正版へ更新した。ライブラリの影響条件と、
アプリから実際にその条件へ到達できるかは区別している。

| リポジトリ | 変更 | 根拠 |
| --- | --- | --- |
| piep | zstd 0.13.3 → 0.13.4、zstd-safe 7.3.0 → 7.4.0 | [ストリーム間の情報漏洩](https://rustsec.org/advisories/RUSTSEC-2026-0391.html)、[範囲外の展開](https://rustsec.org/advisories/RUSTSEC-2026-0398.html)、[未初期化メモリの露出](https://rustsec.org/advisories/RUSTSEC-2026-0403.html) |
| piep-android | webpki-root-certs 1.0.9 → 1.0.10 | [信頼を撤回された中間証明書を受理するルート証明書](https://rustsec.org/advisories/RUSTSEC-2026-0383.html) |

更新後、両リポジトリの `npm audit` と `cargo audit` のvulnerability分類は0件。
Rustの監査には保守終了・unsound・yankedの警告が残る。デスクトップの`lru`はTantivy由来で、
問題にはpanicするキーのDropが必要だが、この利用箇所のキーは`usize`である。`glib`は
Windows・Androidで使わないLinux側の依存である。保守終了の依存については上流更新・置換の追跡が必要。

## 検証と限界

- Node.js 24.22.2とRust 1.99.1を使用。0.38.0への統合後、フロントはPC全851テスト、Android全24テストが成功。
- 統合後、PCのRust全960テストが成功（別途、起動メッセージの1テストも成功。実環境・測定用の12テストは既定で除外）。AndroidのRust全71テストも成功。
  原本JSONを必須にした索引の変更は、実ライブラリ27,801件で原本の欠落が0件であることを読み取り専用で確かめた。
- PCの型検査・lint、両リポジトリの全ターゲットのClippy、PCの整形検査・差分検査・ドキュメント整合性検査が成功。IPC抽出器の6テストも成功。
- Rustの全体検証はメモリ使用を抑えるため`-j 1`、テストは`--test-threads=1`で実行。
- 修正用テストには、実HTTPでの未送信本文の拒否と転送禁止、実ファイルのロックによる同期失敗、バックアップによる既存ファイル保持、接続切替中の画像取得、実ファイルのACL・リンク・外部ACL保持の検査を含む。
- 実ユーザーのライブラリを書き換える検証、SYSTEMタスクの実登録、配布先サーバーへの適用、APK・エミュレーター・実機での確認は行っていない。
- 最新mainにある同期の永続復旧記録を維持し、プロセス強制終了をまたぐ確定・巻き戻しの経路を取り除いていない。
- PDFの上限はRust側の読み込み・抽出作業に対する防御で、Pdfium内部の展開処理を別プロセスへ隔離したものではない。
- フロントの500 kB超チャンク警告と、Android用crateをWindowsで検証する際の既存のlinker出力警告は残る。Android全体の整形検査には、今回変更していない`secret_cipher.rs`のimport順の差分がある。変更したRustファイルの整形検査は成功。
- デスクトップ・単独サーバーは 0.38.1、Android は 0.7.4 として配布した。
