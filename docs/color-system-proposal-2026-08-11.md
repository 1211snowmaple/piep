### 1-3. ここで判明したこと

**青が2種類ある。** `piep`（`#0d86f4`、ブランド色）と Mantine 既定の `blue`（`#228be6`）が、どちらも「情報・主要」の意味で併用されている。

**緑が3種類ある。** `green`（`#40c057`）、`teal`（`#12b886`）、`leaf`（`#86b918`）。意味の重なりは大きい。

- `green` = 成功・完了
- `leaf` = EPUB（ブランド色の片割れ）
- `teal` = 更新監視、検索の一致理由

**同じ概念が、場所によって色があったりなかったりする。** サイドバーの「お気に入り 84」「更新監視 7」は無色のグレーアイコン（`libraryShelves.ts` は色を持たない）。同じ2つがカード上では橙と teal。

## 2. 何が起きているか

問題は「色が多い」ことそのものより、**色が何を意味するのか決まっていない**ことにある。

### 2-1. 色が「機能の区別」に使われている

現状の3つのトグルは、色で互いを区別している。しかし機能の区別は**アイコンの形**の仕事であり、ハート・回転矢印・本＋チェックは既に十分に違う。色を機能に使ってしまうと、**状態（オン/オフ）を表す手段が塗りだけ**になり、しかもその塗りが3色に散る。

### 2-2. 最も意味の遠い2つが、最も似た色をしている

- 更新監視（teal `#12b886`）= 背景処理が定期的に見に行く購読
- EPUB（leaf `#729f12`）= いま書き出そうとしている一時的なカゴ

前者は永続的な設定、後者はセッション限りのカゴ。性質は正反対なのに、並ぶと**どちらも緑**で見分けにくい。

### 2-3. オフに中立がない

`variant="subtle"` でも `color` が効くため、未設定の作品でも色が出る。一覧を「何も設定していない静かな状態」から始められない。

### 2-4. 3つが同列に見えるが、実は種類が違う

| コントロール | 本当の性質 |
|---|---|
| 読む | 画面遷移。トグルではないのに同じ形をしている |
| お気に入り | 読者自身の、永続的で感情的な印 |
| 更新監視 | 背景処理への購読。他の作品と足し合わされて「7件」になる |
| EPUB | 一時的なカゴ。閉じれば消える性質のもの |

5つのボタンが等間隔・同サイズで並ぶことで、**この違いが完全に潰れている**。

---

## 3. 判断の軸 — 色は何に使うのか

色は希少資源で、使い道は3つしかない。

1. **状態**（オン / オフ）
2. **機能の区別**（これはハート、これは更新）
3. **重要度・危険度**（破壊的、警告、成功）

**推奨は 1 と 3 に限る。** 2 はアイコン形状とラベルの仕事であり、色を割くと 1 と 3 に使える色がなくなる。

この方針を採ると、カード上に必要な色は原則**1色（オン）**＋グレー（オフ）になる。

## 4. アイデア

各案は独立ではなく、組み合わせられる。

### 案1: 1色・3段階 — 色は状態だけを表す

トグルは3つとも `piep` 1色。区別はアイコン形状に任せる。

- オフ: グレーの `subtle`（色なし）
- オン: `piep` の `light`（淡い塗り）
- 「読む」だけ常時 `piep` の `filled` か、逆に無色にする

さらに、オンの中でも重みを付けたい場合は**同じ色相の濃淡**で階層を作る。

| | 塗り |
|---|---|
| お気に入り（オン） | `filled`（濃） |
| 更新監視・EPUB（オン） | `light`（淡） |

- **カード1枚の色数**: 1
- **長所**: 一覧が静かになり、サムネイルが主役に戻る。オン/オフが一目で分かる。パレットの憲法（第5節）とも矛盾しない
- **短所**: 「何がオンか」はアイコンを見る必要がある。ただし3種のアイコンは形が大きく違うので実害は小さいと見ている
- **実装量**: 小（`WorkCard.tsx` の `color` 3箇所と `WorkPage.tsx` の2箇所）

### 案2: 状態は完全に無彩色、色は「読む」だけ

トグルはオン・オフともグレーの濃淡で表す（オン＝濃いグレー塗り、オフ＝薄い輪郭）。色を使うのは主要操作の「読む」のみ。

- **カード1枚の色数**: 1
- **長所**: 最も静か。色の意味が「操作できる場所」に一本化される
- **短所**: お気に入りの「印を付けた感じ」が失われる。オン/オフのコントラストがグレー濃淡だけになり、弱い
- **実装量**: 小

### 案3: 1色 + お気に入りだけ例外

お気に入りは読者自身の感情的な印なので、暖色を1つだけ残す。更新監視とEPUBは `piep` かグレーに寄せる。

- **カード1枚の色数**: 2
- **長所**: 現状からの変更が小さく、賑やかさは半分以下になる。ハートが赤系という一般的な連想にも合う
- **短所**: 「なぜハートだけ特別なのか」という一貫性の説明が要る（ただし直感には合う）
- **実装量**: 小

### 案4: 塗るのをやめて「点」で示す

ボタンは常にニュートラル。オンのときだけアイコンの右上に小さなドット（`piep`）を出す。

- **カード1枚の色数**: 1
- **長所**: 塗り面積が激減し、行の重心がオン/オフで変わらない
- **短所**: ドットが小さく、3つ並ぶと判別しづらい可能性。実物を見るまで良し悪しが判断できない
- **実装量**: 中（CSSの追加が要る）

### 案5: 状態表示と操作を分離する

状態は日付・文字数が並ぶメタ行に小さなマークとして出し、切り替え操作は「その他」メニューに入れる。

- **カード1枚のボタン数**: 5 → 1〜2
- **長所**: 一覧が本当に静かになる。状態は「情報」、操作は「メニュー」という素直な整理
- **短所**: お気に入りの切り替えが2クリックになる。頻度の高い操作を遠ざけるのは危険
- **実装量**: 中

### 案6: そもそもカードに出す数を減らす

- 「読む」はカード本体のクリックと**重複している**（カードを押せば詳細、そこから読む）
- 「EPUB」は複数選択のバルク操作に既に存在する

残すのを「お気に入り + 更新監視 + その他」の3つ、あるいは「お気に入り + その他」の2つに絞る。

- **長所**: 色の議論の前に、色を塗る対象そのものが減る。どの案とも組み合わせられる
- **短所**: 1作品ずつEPUBに入れる操作が遠くなる（複数選択かカード詳細から）
- **実装量**: 小

## 5. アプリ全体の「色の憲法」（どの案を選んでも先に効く）

カードだけ直しても、青2種・緑3種が残っていれば統一感は戻らない。役割ごとに色を1つに決め、それ以外を使わない。

| 役割 | 色 | 使う場所 |
|---|---|---|
| 主要操作・現在地・オン状態 | `piep` | ボタン、選択中のタブ、オンのトグル、情報Alert |
| 完了・成功 | `green` | 完了通知、成功アイコン、接続済み、最新 |
| EPUB | `leaf` | EPUBキューの操作だけ |
| 破壊的・失敗 | `red` | 削除、エラー |
| 注意・確認待ち | `yellow` | 警告 |
| 上記以外すべて | `gray` | |
| サービスのブランド色 | 各サービス固有 | `ProviderMark` と外部リンクのマークだけ。**アプリのUIの色ではない** |

**廃止候補**: `blue`（`piep` と重複）、`green`（`leaf` と重複）、`teal`、`violet`、`cyan`、`indigo`。`orange` は案3を採る場合のみ「お気に入り」専用として残す。

置き換えの目安:

- `blue` → `piep`（Alert 9箇所、通知7箇所）
- `green` → `leaf`（成功アイコン、通知21箇所）
- `teal` → `piep`（更新監視、検索一致理由バッジ）
- `violet` → `gray`（ローカル編集バッジ。状態の告知であって危険でも成功でもない）
- `cyan` / `indigo` → ジョブ状態は `piep` / `leaf` / `yellow` / `red` / `gray` の5つに畳む

ジョブ状態は現在 green 11・yellow 6・red 6・orange 5・gray 4・blue 3・cyan 2・violet 1・teal 1 と最も散らかっている箇所なので、ここを畳むと全体の印象が最も変わる。

---

## 6. 推奨

**案1 + 案6 + 第5節の憲法** を推す。

1. まず憲法を決めて、青2種・緑3種を1種ずつに畳む（見た目の変化は大きいが、判断は機械的）
2. カードの操作を「お気に入り + 更新監視 + その他」に絞る（「読む」はカードのクリックと重複、EPUBは複数選択にある）
3. 残る2つのトグルは `piep` 1色。オフは完全に無彩色、オンは淡い塗り。お気に入りだけ濃い塗りにして主従を付ける

結果、カード1行の色は「サムネイル + 提供元マーク + オンのトグル（あれば）」だけになる。

---

## 7. 決めていただきたいこと

1. **お気に入りに専用色を残すか**（案3を採るか）。残すなら暖色1つ、残さないなら `piep` に畳む
2. **「読む」ボタンをカードから外すか**。外すと1行あたりの色付き要素が確実に1つ減る
3. **EPUBボタンをカードから外すか**。バルク操作に一本化してよいか
4. **提供元マーク（pixiv青・FANBOX黄）は現状維持でよいか**。ブランド色なので憲法の外に置くのが妥当だと考えているが、一覧の賑やかさにはこれも寄与している
5. **通知の色**（成功21件が `green`）を `leaf` に寄せてよいか。ブランド色が通知に出ることになる

方針が決まれば、上記の置き換えは機械的な作業になります。実際の見え方を確認したい案があれば、その案だけ実装して並べて比較することもできます。

# 第2版 — 機構と配色を切り分ける

## 8. 決まったこと

| 項目 | 決定 |
|---|---|
| 色の重複 | **畳む。** 青はアプリアイコンの青、緑はアプリアイコンの緑に寄せる |
| 青 | `#0096FA` — アイコン左ページ。`src/assets/icon.svg` に `rgb(0, 150, 250)` として入っている |
| 緑 | `#86B918` — アイコン右ページ。`rgb(134, 185, 24)`、`leaf[5]` と同一 |
| 提供元マーク | **現状維持。** pixiv青・FANBOX黄はブランド色として憲法の外に置く |
| 好みの方向 | ハートは**赤**、**チップの背景ではなくアイコンの中身が塗られる** |

### 8-1. 青について、実際にやることは1つだけ

アイコンの青 `#0096FA` と現行 `piep[6] #0d86f4` は rgb(0,150,250) と rgb(13,134,244) で、**並べても見分けが付きません**。したがって「青を1つにする」の実体は、**Mantine既定の `blue #228be6` を消すこと**です。

`piep` をアイコンと完全に一致させたい場合はスケール全体を `#0096FA` 基準で引き直すことになりますが、見た目の効果はほぼゼロです。

### 8-2. 気付いた副作用

pixivマークも `#0096FA` です。アプリの青をこれに合わせると、**提供元マークとアプリのアクセントが同じ色**になります。pixiv作品が大半のライブラリでは、マークが「アクセントが付いている」ように見える可能性があります。提供元マークは現状維持というご指定なので、これは受け入れる前提で書いています。

| M3 | 線から面へ、色は使わない | 色を1つも消費しない。差は弱い |

## 10. 中身塗りにすると出てくる制約

**中身の塗れるアイコンでないと成立しません。** これは実装上の細部ではなく、機構を選ぶと決まってしまう前提です。

| コントロール | 現行アイコン | 中身が塗れるか |
|---|---|---|
| お気に入り | `Heart` | ○ 閉じた形 |
| 更新監視 | `RefreshCw`（回転矢印） | **× 線だけの形。塗る中身が無い** |
| EPUB | `BookPlus` / `BookCheck` | △ ほぼ線 |

したがって中身塗りを採るなら、**更新監視とEPUBのアイコンを替える**必要があります。候補は次の2つで、どちらも `lucide-react` にあります。

- 更新監視 → `Bell`（ベル）。「新着を知らせる」の標準的な語彙で、閉じた形なのできれいに塗れる
- EPUB → `Bookmark`（しおり）。閉じた形

ただし **`Bookmark` は現在「保存した検索」で使われています**（`icons.ts` の `savedSearch`）。EPUBに転用するなら、そちらのアイコンを見直す必要があります。

### 10-1. ここで案6（数を減らす）と噛み合う

EPUBをカードから外せば、中身塗りが必要なのは**ハートとベルの2つだけ**になり、どちらも問題なく塗れます。アイコンの衝突も起きません。

つまり **「中身塗りが好み」という美的な選択と、「カードのボタンを減らす」という構造的な整理は、同じ方向を指しています。**

## 11. 赤について

いま赤は**削除・エラー専用**です（`color="red"` 27箇所、通知40件）。ハートに同じ赤を使うと、赤の意味が2つになります。

- **同じ `red #FA5252` を使う** — ハートという形が意味を運ぶので、実害は小さいと見ています。塗られたハートを「危険」と読む人はいません
- **`pink #E64980` に分ける** — 破壊的操作と混ざりません。ただしアプリの他のどこにも pink が無いので、単独で浮く可能性があります

比較シートの P3 と P6 で見比べられます。

**M2（中身塗り）× P3（赤ハート + アイコンの青）× 案6（EPUBと「読む」をカードから外す）**

結果、カード1行の操作は次の2つ＋メニューになります。

| 更新監視 | グレーのベル輪郭 | 青の塗りつぶし |

# 第3版 — 実装

決定を受けて実装しました。**M2（グリフの中身を塗る）× P4（赤・青・緑）× 現行アイコン**です。

## 14. カードの操作列

| | アイコン | オフ | オン |
|---|---|---|---|
| 読む | `BookOpen`（現行） | — | 背景なし・青の輪郭 `#0872D3` |
| お気に入り | `Heart`（現行） | 灰 `#868E96` の輪郭 | **赤 `#FA5252` の塗りつぶし** |
| 更新監視 | `RefreshCw`（現行） | 灰の輪郭 | 青 `#0872D3` |
| EPUB | `BookPlus`（現行・**両状態で同一**） | 灰の輪郭 | **緑 `#729F12`** |
| その他 | `Ellipsis` | 灰 | — |

- **チップの背景を全廃**。オン/オフはグリフ自身の色と塗りで表す
- **EPUBのアイコンを両状態で統一**。`BookPlus` ⇄ `BookCheck` の入れ替えをやめた。形と色で同じことを二度言っており、しかも変わる方の形がボタンの用途を示す部分だった
- 作品詳細のお気に入り・EPUBも同じ意味付けに揃えた

### 14-1. 明暗それぞれの値を明示した理由

Mantine の `subtle` は地の色に対するコントラストを取って**シェードを勝手に選びます**。白地では赤が `#C92A2A`（маroon寄り）に、EPUBが `#455B15`（暗いオリーブ）になり、ご指定の「EPUBの緑」から外れていました。暗色テーマではさらに問題で、**全部が shade 0 のほぼ白**になり、フラグの色が消えていました。

そのため `--flag-*` トークンで明暗両方の値を明示し、コンポーネントから `--ai-color` として渡しています。

実測値:

| | 明 | 暗 |
|---|---|---|
| お気に入り | `#FA5252` | `#FF8787` |
| 更新監視・読む | `#0872D3` | `#8DD1FF` |
| EPUB | `#729F12` | `#9DCF49` |
| オフ | `#868E96` | `#8B95A1` |

### 14-2. 途中でつまずいた点

`light-dark()` は**カスタムプロパティ越しにインラインで読むと機能せず、黙って明色側に解決されます**。直接の宣言（`background: light-dark(...)`）では動くので気付きにくい。Mantine の `[data-mantine-color-scheme="dark"]` で切り替える形にしました。

## 15. 色の重複の解消（実施済み）

| 廃止 | 移行先 | 件数 |
|---|---|---|
| `blue` | `piep` | 20 |
| `green` | `leaf` | 28 |
| `teal` | `piep` | 4 |
| `cyan` `indigo` `violet` `grape` | `gray` | 9 |
| `orange` | `yellow` / `gray` / `dimmed` | 11 |

**ジョブの種別色を全廃しました。** 保存・更新・EPUB・バックアップ・復元・検索索引・保守に7色が割り当たっていましたが、これは色を「分類」に使っている典型で、隣のアイコンが既に種別を示しています。種別は灰に統一し、色は**状態**（待機・実行中・完了・失敗・要対応）だけが持ちます。エディタのブロック種別7色も同様に畳みました。

結果、アプリ全体で使われる色は5つになりました。

| 役割 | 色 | 件数 |
|---|---|---|
| 中立 | `gray` / `dimmed` | 94 / 155 |
| 破壊的・失敗 | `red` | 81 |
| 主要操作・状態・情報 | `piep` | 33 |
| 完了・成功 | `green` | 50 |
| EPUB | `leaf` | 2 |
| 注意・要対応 | `yellow` | 17 |

提供元マーク（pixiv `#0096FA` / FANBOX `#F2C624`）はご指定どおり現状維持。アプリの青も現行 `piep #0d86f4` のままです。

## 16. オン状態の背景（追加）

グリフだけでは白地に対して線が細く、視認性が落ちるという指摘を受けて、**明色テーマのみ**オンのフラグに自分の色の薄い背景を戻しました。暗色テーマでは明るいグリフ自体が十分に目立ち、背景を敷くと行が濁るため、背景なしのままです。

| | 明色テーマ | 暗色テーマ |
|---|---|---|
| お気に入り（オン） | `rgb(250 82 82 / 13%)` | 背景なし |
| 更新監視（オン） | `rgb(8 114 211 / 11%)` | 背景なし |
| EPUB（オン） | `rgb(114 159 18 / 15%)` | 背景なし |
| オフ・読む | 背景なし | 背景なし |

元の実装との違いは**濃さ**です。以前は不透明の塗り（白抜きアイコン）でしたが、今回は13〜15%の淡い敷き色で、アイコンは自分の色のまま残ります。一覧が騒がしくならずに、オンであることが一目で分かります。

検証: `tsc` 通過、単体182件通過、Playwright 35件通過、ビジュアル回帰のベースラインを更新。

# 第4版 — 診断画面と説明文の扱い

## 17. 診断は開いても勝手に始まらない

`useQuery` がマウント時に走っていたため、画面を開いただけで**保存フォルダー全体の走査と3種類のベンチマーク**が始まっていました。大きなライブラリでは数十秒のディスク処理で、その間ライブラリの読み書きも遅くなります。

`enabled: false` にして、明示的に押されたときだけ計測します。未計測のときは空状態と「計測する」ボタン、計測後はヘッダーに「再計測」。**すでに計測済みの結果はキャッシュから即座に表示されます** — 待たせるのは*実行*であって*表示*ではないので。

ついでに、設定に埋め込まれているときに「ブラウザプレビュー」の帯が二重に出ていたのも直しました（設定画面が既に上部に出しているため）。

## 18. レイアウト崩れ

実測して2箇所の切り詰めを確認しました。

| 箇所 | 症状 | 原因 | 対応 |
|---|---|---|---|
| メトリクスカードの数値 | `2,23…` `100.0…` | 設定内の幅で4列だと、数値に**64px**しか残らない | 4列は `xl` 以上のみ。アイコンを44→38pxに縮小し、数値は `clamp()` で幅に応じて縮む |
| 性能テーブルのバッジ | `12…` `69…` | 半分幅のカードに4列表は入らず、バッジが**27px**に潰れる | `Table.ScrollContainer` で横スクロール。バッジは切り詰めず全長を表示 |

**数値は折り返しても切り詰めない**方針にしました。`2,23…` は別の数字に読めてしまうので。修正後、切り詰め要素はゼロです（実測）。

あわせて、レイテンシのバッジが `8.3 MS` と大文字化されていたのも `tt="none"` で直しました。

## 19. 説明文の背景色

設定画面のAlertを実測したところ、**同じ「説明」が3種類の背景**に散っていました。

| 背景 | 内容 |
|---|---|
| `#d8efff`（piep） | 「再構築中も検索は使えます」「安全な復元」 |
| `#e7f3cf`（leaf） | 「接続情報を外部へ送信しません」 |
| `#f1f3f5`（gray） | 「索引づくりはCPUの処理です」「公式アプリではありません」 |

どれも状態ではなく**仕組みの説明**で、色の違いに意味がありませんでした。

新しい色は足さず、**色を使わない見た目**を1つ作りました（`Note`）。塗りなし・ヘアライン枠・控えめな文字・小さなアイコン。

| 種類 | 見た目 |
|---|---|
| **説明・補足** | `Note`（無彩色・枠線のみ） |
| 注意 | `Alert color="yellow"` |
| 失敗・不可 | `Alert color="red"` |
| 完了 | `Alert color="leaf"` |
| 該当なし | `Alert color="gray"` |
| 環境の告知 | `RuntimeNotice`（piepの帯・画面上部に1つ） |

`Alert` は**本当に状態があるときだけ**使います。説明が色を持たなくなったので、黄や赤が出ていれば必ず意味があります。

変換したのは設定の3件に加え、作品詳細「編集について」、更新センター、作者ページのプレビュー注記。

検証: `tsc` 通過、単体183件通過、Playwright 35件通過、ビジュアル回帰のベースラインを更新。

# 第5版 — 緑を2つに戻す

## 20. 強調の緑とEPUBの緑は別物だった

第3版で `green` を `leaf` に畳んだのは**やりすぎ**でした。接続済み・最新・完了・成功のバッジまで EPUB のオリーブ green になり、「完了した処理がすべてEPUBに見える」状態になっていました。

区別を戻しました。

| 役割 | 色 | 使う場所 |
|---|---|---|
| 完了・成功・接続済み・最新 | `green` `#40C057` | 通知、成功アイコン、進捗バー、状態バッジ |
| **EPUB** | `leaf` `#729F12` | **EPUBキューの操作のみ**（カードのトグルと作品詳細のボタン、計2箇所） |

`leaf` はワードマークの「ep」の緑、つまり**機能の名前**です。成功は機能ではないので別の緑を持ちます。50箇所を `green` に戻し、`leaf` を残したのは2箇所だけです。

あわせて、ホーム画面の検索インデックスで**バッジは緑・その下の進捗バーは青**という食い違いがあったのも直しました（同じ数字の2つの読み方になっていた）。

検証: `tsc` 通過、単体183件通過、Playwright 35件通過、ビジュアル回帰のベースラインを更新。
